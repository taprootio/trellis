# TRL0008 — Viewer: dependency graph and effort filter

## Scope

- **Data.** Read `GET /api/backlogs/<id>` from `trellis serve` (TRL0005)
  for each selected backlog, never a committed `backlog.json`, which
  TRL0038 can remove. Edges and readiness stay within one backlog.
- **Readiness.** An active task is ready when every direct prerequisite in
  `depends_on` resolves to a `completed` task, including when it has none.
  An active, removed or unresolved prerequisite blocks it. Readiness is
  computed on the backlog's full task set before any display filter, so
  hiding a prerequisite never makes its dependent look ready. A task whose
  `depends_on` was missing (the API marks it with `dependsOnMissing:
  true`, since serialization turns it into `[]`) gets no ready flag.
- **Graph.** A "Graph" control in the viewer opens a view, for one
  backlog at a time, that renders `depends_on` as directed edges from
  prerequisite to dependent, with blocked and ready flags on active nodes.
  It uses Espalier components like the rest of the viewer.
  - Completed and removed nodes are collapsed by default. A dependent
    still shows a compact marker for each collapsed prerequisite, and one
    control expands them.
  - Clicking a node opens `/b/<backlog>/task/<ID>`.
- **Effort.** An exact-match effort filter combines with TRL0005's
  backlog, status, milestone, priority and owner filters in the query
  string, and also narrows search hits. Its value is the canonical number,
  and its options are the numeric efforts present on the tasks currently
  shown after the other filters. A sort orders tasks numerically by
  canonical `effort` within each backlog and milestone, never
  alphabetically by label, and puts tasks with a missing or invalid effort
  last. While a search term is set, TRL0005's rank order stays and the
  effort sort does not apply.
- **Live.** The graph and flags update on the same Server-Sent Events
  reload as the task list.

## Acceptance

- `node --test` covers these, against a temporary repo served by
  `trellis serve` and the viewer's pure modules:
  - A known pair's edge points from prerequisite to dependent. Moving the
    prerequisite to `completed/tasks/` turns the dependent from blocked to
    ready on the next SSE refetch.
  - A task with no `depends_on` field gets no ready flag.
  - With effort sort on, a task with no effort sits after 5 and 13.
  - A dependent with an unresolved prerequisite id is blocked.
  - Filtering by effort together with a milestone filter returns only
    cards matching both, and the effort sort puts 5 before 13.
- `npm run backlog:check` and `node --test` exit 0.

## Risks

  as above.

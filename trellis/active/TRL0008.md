# TRL0008 — Viewer: dependency graph and effort filter

## Scope

- **Data.** Read `GET /api/backlog` from `trellis serve` (TRL0005), never
  a committed `backlog.json`, which TRL0038 can remove. Use the resolved
  `tasks` set, which TRL0041 builds from the served tree plus lane
  overlays, and each `inFlight[].task` (TRL0041), which carries a lane's
  own version of an item.
- **Readiness.** An active task is ready when every direct prerequisite in
  `depends_on` resolves to a `completed` task, including when it has none.
  An active, removed or unresolved prerequisite blocks it. Readiness is
  computed on the full resolved set before any display filter, so hiding
  a prerequisite never makes its dependent look ready. A task whose
  `depends_on` was missing (the API marks it with `dependsOnMissing:
  true`, since serialization turns it into `[]`) gets no ready flag. Each
  `inFlight` entry also gets its own lane flag, computed from
  `inFlight[].task`, and shown on that lane's badge. Its prerequisites
  resolve from that lane's full task snapshot (`lanes[].tasks`, TRL0041),
  including the lane's unchanged items, never from the served tree, so a
  prerequisite closed on the served branch after the lane branched still
  blocks the lane badge. A lane edit to
  a served item's `depends_on` or `status` therefore shows up even though
  the card shows the served version.
- **Graph.** A "Graph" control on the board opens a view that renders
  `depends_on` as directed edges from prerequisite to dependent, with
  blocked and ready flags on active nodes.
  - Completed and removed nodes are collapsed by default. A dependent
    still shows a compact marker for each collapsed prerequisite, and one
    control expands them.
  - Clicking a node opens `/task/<ID>`.
- **Effort.** An exact-match effort filter on the active board combines
  with TRL0005's milestone, priority and owner filters in the query
  string. Its value is the canonical number, and its options are the
  numeric efforts present on active resolved cards, so a lane card's
  effort is selectable. A sort orders cards numerically by canonical
  `effort` within each milestone group, never alphabetically by label,
  and puts cards with a missing or invalid effort last in their group.
- **Live.** The graph and flags update on the same Server-Sent Events
  reload as the board.

## Acceptance

- `node --test` covers these, against a temporary repo served by
  `trellis serve`:
  - From the board, the Graph control opens the graph, and a known pair's
    rendered edge points from prerequisite to dependent. With the graph
    still open, moving the prerequisite to `completed/tasks/` turns the
    dependent from blocked to ready without a manual reload.
  - A lane that edits a dependent and completes its prerequisite in the
    same lane shows that lane's badge ready, while the served card stays
    blocked.
  - A task with no `depends_on` field gets no ready flag.
  - When the served checkout closes a prerequisite after a lane branched
    and the lane edits the dependent, the served card is ready and the
    lane badge stays blocked.
  - With effort sort on, a card with no effort sits after 5 and 13.
  - A dependent with an unresolved prerequisite id is blocked.
  - Filtering by effort together with a milestone filter returns only
    cards matching both, and the effort sort puts 5 before 13.
  - A lane edit that adds an active prerequisite to a served item marks
    that lane's badge blocked, while the served card stays ready.
- `npm run backlog:check` and `node --test` exit 0.

## Notes

- Milestone, priority and owner filters, and effort label, emoji and image
  rendering, belong to TRL0005.

## Risks

- Graph clutter at scale. Mitigation: collapsed closed nodes and markers,
  as above.

# TRL0040 — Onboard a repo that already runs good-agent and its own CI

## Problem

`trellis init` (`src/init.mjs`) always scaffolds the same set of files:

- `.github/workflows/backlog.yml` and `.github/pull_request_template.md`;
- the four playbooks under `trellis/playbooks/`;
- an AGENTS.md block of about 2 KB that points the work and review loops at
  those playbooks.

For a repo that already uses good-agent, the playbooks duplicate the
`write-task`, `work-task` and `review-loop` skills. Two copies of the loop
drift, which is what good-agent exists to prevent.

For a repo with its own CI, the extra workflow duplicates an existing gate.
In Taproot it would also be a protected workflow change, which forces a
full-CI run.

Taproot's `AGENTS.md` is 32,613 bytes. Appending the block would push it past
the 32,768 bytes Codex reads, and good-agent's `codex/size-budget` rule would
fail.

## Scope

- **`--skip <parts>` (`scripts/trellis-init.mjs`, `src/init.mjs`).** A
  comma-separated list from `ci`, `pr-template`, `playbooks`,
  `branch-protection` and `agents`. A skipped part is neither written nor
  reported as missing. Unknown names are a usage error (exit 2). `--dry-run`
  lists what is skipped.
- **good-agent detection.** When the target has `good-agent.config.json`, or
  `.agents/skills/work-task/SKILL.md`, init skips `playbooks` unless
  `--with-playbooks` is passed, and writes the compact block below. The
  output says what it detected and that it skipped the playbooks.
- **Compact AGENTS.md block.** Inside the same `BEGIN/END TRELLIS` markers,
  the block holds:
  - one line naming the backlog root and the config path;
  - the regenerate and check commands;
  - the Loop contract table;
  - one sentence saying that task work follows good-agent's `write-task`,
    `work-task` and `review-loop` skills.

  The full block stays the default when good-agent is absent. A test pins
  the compact block's size, which must stay under 1,200 bytes.
- **Blocks follow what was written and the modes.**
  - When `playbooks` or `branch-protection` is skipped, the full block
    leaves out the lines that point at `trellis/playbooks/` or
    `trellis/branch-protection.md`.
  - Both the full and the compact block, in ledger mode (TRL0037), tell
    AI tools to claim ids with `trellis claim --title`. In local mode
    (TRL0038), they say the index is generated into `.generated/`.
  - When `ci` is skipped, the full block leaves out the lines about the
    `backlog` job gating merges and CI running `check`.
  - Any re-render of an existing TRELLIS block, including TRL0038's
    `--switch-to-local`, keeps the variant already there (full or compact),
    writes nothing when `--skip agents` is given, and passes through the
    size guard below.
  - The compact block's 1,200-byte test uses a ledger plus local config.
- **Size guard.** Before writing AGENTS.md, init computes the result's size.
  If it would exceed 32,768 bytes, init writes nothing to AGENTS.md, prints
  the block on stdout, says how many bytes it needs, and exits 0 with a
  warning, leaving the placement to the owner. The other files are still
  written.
- **MCP prompts without playbooks.** Today `src/prompts.mjs` throws
  `not_found` for the `work-task`, `code-review` and `pr-draft` prompts when
  `trellis/playbooks/` is absent. In that case, when good-agent is detected
  (same test as above), the prompt returns a short message naming
  good-agent's `write-task`, `work-task` and `review-loop` skills.
  Otherwise it says the playbook is absent and points at `trellis init
  --with-playbooks`. Init's output
  says the same when it skips the playbooks.
- **Release.** This story lands last of TRL0037–TRL0040 and bumps
  `package.json` `version` from 0.2.0 to 0.3.0 in its PR, with the matching
  version fields in `package-lock.json`. The merge to main
  then publishes the release (`.github/workflows/release.yml`).
- **Docs.** README "Onboard a repo" and `docs/import.md` describe `--skip`,
  the detection, the size guard and the MCP prompt behavior.

## Acceptance

- `node --test` covers these:
  - Each `--skip` part on its own, and an unknown part (exit 2).
  - Detection through each of the two marker files, and `--with-playbooks`
    overriding it.
  - The compact block's content and its byte ceiling.
  - The size guard on an AGENTS.md of 32,600 bytes: the file is unchanged
    and the block is printed.
  - Each of the three MCP prompts, with playbooks absent, returns the
    good-agent message when good-agent is detected, and the
    `--with-playbooks` message when it is not.
  - `--skip playbooks,branch-protection` without good-agent writes a full
    block with no path to a skipped file.
  - Both blocks carry the claim and `.generated/` wording under a ledger
    plus local config.
  - The default output for a repo with neither condition is byte-identical
    to before; existing tests pass untouched except the version literal.
- `npm run backlog:check` and `node --test` exit 0.

## Notes

- Rejected: removing the playbooks from Trellis. They serve repos without
  good-agent, and the MCP prompts (`src/prompts.mjs`) read them.
- Rejected: shortening the default block. Repos without good-agent need the
  loop pointers it carries.
- TRL0036, on branch `je/trl0036/adopt-good-agent` until merged, adopts
  good-agent in this repo. The playbooks here stay, because
  they are the source that `init` copies and the MCP server serves.

## Risks

- Detection by file presence can misfire on a repo that has good-agent
  installed but does not use its loop. Mitigation: `--with-playbooks`
  restores them, and the output says what was detected.

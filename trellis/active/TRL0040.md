# TRL0040 — Onboard a repo that already runs good-agent and its own CI

## Problem

`trellis init` (`src/init.mjs`) always scaffolds the same set of files:

- `.github/workflows/backlog.yml` and `.github/pull_request_template.md`;
- the four playbooks under `trellis/playbooks/`;
- an AGENTS.md block of about 2 KB that points the work and review loops at
  those playbooks.

For a repo that already uses good-agent, the playbooks duplicate the
`write-task`, `work-task` and `review-loop` skills. Two copies of the loop
drift, which is what good-agent exists to prevent.

For a repo with its own CI, the extra workflow duplicates an existing gate.
In Taproot it would also be a protected workflow change, which forces a
full-CI run.

Taproot's `AGENTS.md` is 32,613 bytes. Appending the block would push it past
the 32,768 bytes Codex reads, and good-agent's `codex/size-budget` rule would
fail.

## Scope

Terms: the **full block** is today's AGENTS.md block. The **compact block**
is the new short one. "Detected" means good-agent detection, defined below.
CLI exit codes keep every code they have today: 0 success (including the
size-guard warning); 1 a scaffold or write failure, including ordinary
`applyScaffold` refusals (preflight, a bad existing config); 2 a usage error
or a refusal with nothing written (unknown flag, `--id-floor`, import flag
errors, the `--force` refusals for ledger, local and legacy configs, the
switch's `OutputRefused`). This task adds to code 2 the new `--skip` and
`--with-playbooks` usage errors and the switch's size refusal, and changes
no existing code.

Literal test tokens (exact strings, so tests never assert prose). The
prompt tokens are one exported constant in `src/prompts.mjs`
(`PROMPT_TOKENS`), emitted by the code and imported by the tests:
- `PROMPT_TOKENS.handoff` = `[trellis:playbook-missing]`, the first line of
  every missing-playbook handoff;
- `PROMPT_TOKENS.noTemplate` = `[trellis:no-template]`, added to the
  `pr-draft` handoff when `.github/pull_request_template.md` is absent;
- `PROMPT_TOKENS.prFlow` = `[trellis:repo-pr-flow]`, on the line of the
  detected `pr-draft` handoff that points at the repo's own PR flow.

The init tokens are one exported constant in `src/init.mjs`
(`INIT_TOKENS`), each starting its own output line:
- `INIT_TOKENS.blockNotUpdated` = `[trellis:block-not-updated]`, the
  recovery line (the TRELLIS block is not updated and the playbook pointers
  are added by hand); it also appears in `--help`;
- `INIT_TOKENS.carryOver` = `[trellis:carry-over]`, the carry-over warning;
- `INIT_TOKENS.preview` = `[trellis:preview]`, the dry-run print marker;
- `INIT_TOKENS.size` = `[trellis:size]`, the size warning.

Everything else in init output is asserted through numbers and flag names,
not prose. Completion-message tests read every line from `Done.` onward,
not the first line alone: under `--skip ci`, `trellis check` is present and
`` `backlog` `` is absent; under `--skip branch-protection`, the recipe link
`branch-protection.md` is absent. The incompatible-flag diagnostic is
asserted by both flag names.

Compact-block literal substrings (written here, not pulled from the
renderer; the renderer keeps each one on a single line). The committed
compact bullet contains both of these exact lines' text:

```
`backlog.json` is generated in full (it has no markers)
the `BEGIN GENERATED` / `END GENERATED` markers apply only to the Markdown files
```

The "generated-marker
references are gone" check after a switch is the three exact strings
`BEGIN/END GENERATED`, `BEGIN GENERATED` and `END GENERATED`, never a
case-insensitive `generated` (that matches `.generated/`).

Markdown tokens (files, so the tests hold the strings):
- `pr-draft.md` headings `## With a PR template`, `## Without a PR
  template` and `## Title and attribution (both branches)`;
- the guide's `your CI status` (it appears in the intro, the setup steps and
  the "Verify the gate" paragraph), the replaceable payload value
  `"contexts": ["<your-ci-status>"]`, the line `Use PUT only to create a
  new protection rule`, and the conditional phrase `if you installed
  Trellis's workflow`. The guide names `backlog` only inside that
  conditional example: its heading becomes "The required-check context"
  (no `backlog` in it), and the YAML snippet and the `backlog` context
  paragraph sit in one bounded section under the subheading `### Example:
  if you installed Trellis's workflow`, which ends at the next line
  matching `/^## /m` (a generic heading matcher would split on the fenced
  YAML comment line `# .github/workflows/backlog.yml`). The
  `not Backlog Hygiene` sentence stays inside it, and the existing
  tolerant regex ``/not `?Backlog Hygiene/`` matches it. Outside that
  section `backlog` appears nowhere (the edit list is in step 6).
- the `## Without a PR template` branch's output: one copy-ready Markdown
  block whose first line is `# <ID>: <summary>`, followed by a description
  written to the repo's own PR instructions.

- **`--skip <parts>` (`scripts/trellis-init.mjs`, `src/init.mjs`).** A
  comma-separated list from `ci`, `pr-template`, `playbooks`,
  `branch-protection` and `agents`. `src/init.mjs` owns the part names and
  the files each part covers, and both the CLI and `applyScaffold` use that
  one table. `agents` covers AGENTS.md: no create, append or print, and it
  takes precedence over both print paths below. The other four cover the
  workflow, the PR template, the four playbooks and the branch-protection
  guide. `planScaffold` applies the table to AGENTS.md before it plans
  that file, since AGENTS.md sits outside `templateFiles`. With `agents`
  omitted, AGENTS.md is also left out of the reconciliation scan, so it
  produces no advisory.
  - It applies only to ordinary scaffolding. `--switch-to-local --skip
    <valid part>` is already a usage error (exit 2) through the switch's
    existing "takes only --dry-run and a target" check; a test pins it.
    So are `--retire-source` with `--skip <valid part>` or with
    `--with-playbooks` (new check beside the existing retire checks).
    Tests use a valid value so a missing-value error cannot mask the guard.
  - A missing or blank value (for example `--skip --force`, `--skip=`,
    `--skip ,`) and unknown names are usage errors (exit 2), checked before
    any prompt or write.
  - A skipped part is neither written nor reported as missing, and it is
    not listed under "skipped" (that list is for files that already
    exist). The summary has a separate `omitted` list of part names (not
    file paths), and the CLI prints one `omitted (n): …` line, in
    `--dry-run` too. A playbook omission caused by detection appears there
    too. The summary also carries `detected` (the matched marker file, or
    null) and `playbooksOmittedBy`, which is `"detection"`, `"skip"` or
    `null`.
  - Repeated `--skip` values accumulate as a union, and so do comma lists:
    `--skip ci --skip playbooks` skips both. `--help` says so.
- **good-agent detection.** One helper in `src/init.mjs` (`detectGoodAgent`)
  owns the test and the MCP prompts reuse it. The target is detected when
  it has `good-agent.config.json` or `.agents/skills/work-task/SKILL.md`,
  each only as a regular file (a directory at a marker path is not a
  marker). When detected, init skips `playbooks` unless
  `--with-playbooks` is passed, and writes the compact block. With
  `--with-playbooks` the playbooks are written and the full block is used,
  since its pointers then resolve. Not detected: nothing changes, and
  `--with-playbooks` is accepted, writes nothing extra and prints nothing.
  `--skip playbooks --with-playbooks` and `--switch-to-local
  --with-playbooks` are usage errors (exit 2) before any write. A rerun with
  `--with-playbooks` writes only what it is told to, so the owner repeats
  any other `--skip` flags; the help text says so. The output names the
  detected marker file and says the playbooks were left out because of
  it. When a repo that is not detected explicitly skips `playbooks`, the
  output prints `trellis init --with-playbooks` as the way to add them,
  and says the TRELLIS block is not updated, so the playbook pointers must
  be added by hand. `--help` and the docs say the same.
- **Compact block.** Inside the same `BEGIN/END TRELLIS` markers, it holds:
  - one line naming the backlog root and the config path;
  - one sentence saying that task work follows good-agent's `write-task`,
    `work-task` and `review-loop` skills;
  - in ledger mode, the claim line (below);
  - one artifact bullet per mode. Committed: the README and index tables
    are generated between the `BEGIN/END GENERATED` markers and
    `backlog.json` is generated in full (it has no markers). Local: the
    index is generated into `.generated/`. `artifactBullet(root, mode,
    variant)` stays the one owner of every artifact text;
  - the regenerate and check commands, which sit in the Loop contract
    table below, so there is no separate command line;
  - the Loop contract table, with the same five rows as the full block.

  The full block stays the default when good-agent is absent, and its bytes
  do not change for a repo with no skips, no ledger and no detection. A test
  pins the compact block's size for a ledger plus local config with a short
  `tasksDir`: under 1,200 bytes (the draft measures about 1,000). Real
  repos are bounded by the size guard instead, since a long `tasksDir`
  lengthens the block.
- **Blocks follow what was written and the modes.**
  - The claim line: in ledger mode (TRL0037), both blocks tell AI tools to
    claim ids with `npx @taprootio/trellis claim --title "<one line>"` and
    not to pick the next number by hand. In the full block it is its own
    bullet, placed before the artifact bullet, never a continuation of it. `planScaffold` reads this from
    the kept config's `idAllocation`; a fresh scaffold is never ledger. In
    scan mode the line is absent, so existing output is unchanged. In
    local mode (TRL0038), both blocks use the `.generated/` bullet.
  - `playbooks` skipped: the full block leaves out the paragraph and the
    closing line that point at `trellis/playbooks/`, and keeps the Loop
    contract table with a one-line lead-in that names no file.
  - `branch-protection` skipped: the full block leaves out the recipe link.
  - `ci` skipped: the full block leaves out the clause that CI runs
    `check` and the clause that the `backlog` job gates the merge, and
    keeps "`main` is protected — work on a branch and open a PR".
  - Ordinary init never rewrites an existing TRELLIS block: with one
    present it skips AGENTS.md, as today. The only code that edits an
    existing block is TRL0038's `--switch-to-local`. It replaces only the
    artifact bullet, recognizing the exact full or compact text of the
    committed mode and writing the same variant's local text, so a block
    keeps its variant and any line a skip left out stays out. Its
    already-local check (`src/switch-local.mjs`, the `findWholeLines(block,
    local)` test) accepts both the full and the compact local text, so a
    rerun on a migrated compact block gives no warning and no edit. A
    bullet that matches neither is left alone with a warning, as today.
    Its closing message says to run `trellis init` repeating the same
    `--skip` flags, not plain `trellis init`, which would recreate the
    skipped parts.
  - `--with-playbooks` never rewrites an existing TRELLIS block (scope cut,
    2026-11-19). When good-agent is detected and a block exists, it writes
    the playbooks, leaves AGENTS.md untouched, and prints the full block
    for the owner to place by hand. `--skip agents` wins: nothing is
    printed or written for AGENTS.md. Without detection, the flag changes
    nothing.
  - Whenever init prints a block (this case and the size guard), it also
    prints a warning telling the owner to carry over the Loop contract
    values the repo already uses. One helper owns that warning.
- **Init's own output follows the skips.** With `--skip ci`, the
  completion message tells the owner to require `trellis check` through
  their existing CI (SPEC §10), not a `backlog` job that was never created.
  With `--skip branch-protection`, the message leaves out the recipe link.
  `trellis/branch-protection.md` and its packaged mirror under
  `templates/` stay one universal text, identical in both (one edit, two
  files), so there is no separate `--skip ci` copy. The intro sentence, the
  setup steps, the "Verify the gate" paragraph and the `PUT` payload tell
  owners to require the status of their own CI job that runs `trellis
  check`. `backlog` stays only as a conditional example ("the `backlog`
  job, if you installed Trellis's workflow"). The tokens `test/init.test.mjs`
  already requires stay (`backlog`, `not Backlog Hygiene`, `gh api`). The
  `PUT` example is scoped to creating a new protection rule, with a line
  saying that `PUT` replaces an existing rule's settings, so an existing
  rule is edited in the UI instead.
- **`pr-draft` without a PR template.** The `pr-draft` playbook is
  restructured into two explicit branches. `## With a PR template` holds
  the template-gathering and filled-template output steps; `## Without a PR
  template` says only to follow the repo's own PR instructions and never
  tells the reader to collect or fill a template. The shared introduction
  is template-neutral: the existing template link and the conformance
  requirement move into `## With a PR template`. The title and
  attribution rules sit once under `## Title and attribution (both
  branches)`. Both the live playbook and its packaged copy get
  the identical edit. The copied `.github/pull_request_template.md` header
  comment points at `trellis/playbooks/pr-draft.md`, which is skipped by
  default under detection, so that path is dropped from the live and
  packaged copies; the `attribution policy (AGENTS.md)` wording stays.
  The MCP `pr-draft` prompt: with the playbook present it returns it as
  today, and its explicit no-template branch handles a missing template.
  An older `pr-draft.md` copy may lack that branch. Without `--force`,
  init keeps existing files; `--force` overwrites in scan and committed
  repos and is refused for ledger, local and legacy configs. The owner's
  fix is to merge the new no-template branch into the old file (no rerun
  needed), or to move the old `trellis/playbooks/pr-draft.md` aside and
  rerun `trellis init --with-playbooks` with their other `--skip` flags
  and `playbooks` dropped from `--skip`. A bare rerun still omits
  playbooks when good-agent is detected. With the playbook
  absent it returns the missing-playbook handoff below, and when the
  template is also absent the same handoff adds that no template exists
  and none should be filled.
- **Size guard.** `AGENTS_BYTE_LIMIT` (32,768) lives in `src/init.mjs`
  (exported in step 4, with the existing-block reporter), and the switch
  imports it. Before writing AGENTS.md, init computes the
  result's byte length. If it would exceed the limit, ordinary scaffolding
  writes nothing to AGENTS.md, prints the block on stdout, prints a warning
  with the bytes needed, the limit and the remedy (trim AGENTS.md, or place
  the block by hand), plus the carry-over warning, and
  exits 0, leaving the placement to the owner. `applyScaffold` routes this
  print action to reporting before the file-write loop, so the file is
  never written. The other files are still written. Both print paths use
  one summary shape, `summary.printed = [{ reason, block, bytesNeeded }]`
  (`reason` is `size` or `existing-block`; `bytesNeeded` is the full
  would-be size of AGENTS.md in bytes, printed next to the 32,768 limit:
  the exact planned AGENTS.md content, measured with `Buffer.byteLength`:
  for `size` on an append, `cur + sep + block`; on a create, `# AGENTS\n\n`
  plus the block; for `existing-block`, `cur.slice(0, bi) + block.trimEnd()
  + cur.slice(ei + end.length)`, where `bi` and `ei` are the begin-marker
  and end-marker offsets found through `AGENTS_MARKERS`). The 1,200-byte
  ceiling applies to the block only, and a dry run prints the block
  and says it would print. For `--switch-to-local` (TRL0038), an AGENTS.md edit that pushes the file
  across the limit (before at most the limit, after over it) is a
  preflight refusal (exit 2, nothing changed): it is computed in memory
  with the other edits, so it refuses before the config or any file is
  touched and before any removal command is printed. A file already over
  the limit before the edit gets a warning and the switch proceeds. The
  refusal also names the byte count, the limit and the remedy. Sizes use
  `Buffer.byteLength`.
- **MCP prompts without playbooks.** Today `src/prompts.mjs` throws
  `not_found` for the `work-task`, `code-review` and `pr-draft` prompts when
  their playbook is absent. The fallback applies per prompt, whenever that
  prompt's own playbook file is missing, so a directory holding only
  `code-review.md` still serves `work-task` through the fallback. In that case, when
  detected, the prompt returns a short message naming good-agent's
  `write-task`, `work-task` and `review-loop` skills (`work-task` and
  `code-review`), or only `review-loop` and the repo's own PR flow
  (`pr-draft`, which does not get the three skills). The `pr-draft`
  handoff never embeds the playbook body.
  Otherwise it says the playbook is absent and points at `trellis init
  --with-playbooks`. Init's output says the same when it skips the
  playbooks. The `work-task` fallback validates the requested id with the
  same `requireId` as the normal prompt and names that id in its handoff.
  `requireId` accepts an id when it matches TRL0037's `ledgerIdMatcher`
  (the escaped, literal id format) or when it matches the scan-mode
  pattern `check` uses (`scanIdPattern`) and resolves to an existing task
  file, so both paths follow one rule. For a prefix with a regex character
  this rejects a wrong id with no file and still serves a file `check`
  reads.

- **Docs.** README "Onboard a repo", `docs/import.md` and `init --help`

  MCP prompt behavior.

## Notes

- Rejected: removing the playbooks from Trellis. They serve repos without
  good-agent, and the MCP prompts (`src/prompts.mjs`) read them.
- Rejected: shortening the default block. Repos without good-agent need the
  loop pointers it carries.
- TRL0036 adopted good-agent in this repo. The playbooks here stay, because
  they are the source that `init` copies and the MCP server serves.

- Release: merging this branch publishes package release 0.3.0, which carries
  TRL0037, TRL0038, TRL0039 and TRL0040 together.

## Risks

- Detection by file presence can misfire on a repo that has good-agent
  installed but does not use its loop. Mitigation: `--with-playbooks`
  restores them, and the output says what was detected.
- A repo that uses good-agent only for `check` has the marker file but may
  not have the skills installed, so its compact block names skills it may
  lack. Mitigation: `--with-playbooks` restores the full playbooks, and the
  output says what was detected.

## Refinements

Decisions taken at plan time (2026-11-20). Threat model as in SPEC §3.1:
cooperating writers and trusted config. Unusual layouts are refused, not
handled. The AGENTS.md block stays byte-for-byte unchanged for a repo with
no skip, no good-agent and no ledger; a fixture pins this.

Stale or tightened points in the story, checked against the code:

- `agentsBlock` has no ledger awareness and never mentions `claim`, so the
  claim line is new text in both blocks, ledger mode only. `planScaffold`
  already reads the kept config, so it passes the mode in.
- `planScaffold` never re-renders an existing block: it skips AGENTS.md when
  `BEGIN TRELLIS` is present. The only editor is `switchToLocal`
  (`src/switch-local.mjs`), which swaps the artifact bullet on an exact
  match of `artifactBullet`. The story's "re-render keeps the variant, and
  `--skip agents` writes nothing" has no code to attach to, so Scope now
  says what is true: ordinary init never rewrites, and the switch keeps the
  variant because it matches the exact full or compact text.
- `--switch-to-local` already rejects every flag except `--dry-run` through
  its `extra` check, so `--skip` and `--with-playbooks` with it need only a
  test. `--retire-source` has no such guard, so it gets a new check.
- `artifactBullet` is the single owner of the artifact text, and
  `switchToLocal` matches it exactly. Its signature gains an optional
  third argument (`variant`, default full), so the full text and its
  callers do not change.
- `switchToLocal` builds every edit in memory before installing any, so the
  size check slots in after step 5 and refuses before the config edit and
  before any removal command is printed. The refusal is the same
  `OutputRefused` (exit 2) the other preflight checks use.
- `copySourcePath` prefers the live `trellis/…` copy over `templates/`,
  and `test/cli.test.mjs` (`TEMPLATE_PAIRS`) and `test/prompts.test.mjs`

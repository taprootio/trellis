# TRL0040 — Onboard a repo that already runs good-agent and its own CI

## Problem

`trellis init` (`src/init.mjs`) always scaffolds the same set of files:

- `.github/workflows/backlog.yml` and `.github/pull_request_template.md`;
- the four playbooks under `trellis/playbooks/`;
- an AGENTS.md block of about 2 KB that points the work and review loops at
  those playbooks.

For a repo that already uses good-agent, the playbooks duplicate the
`write-task`, `work-task` and `review-loop` skills. Two copies of the loop
drift, which is what good-agent exists to prevent.

For a repo with its own CI, the extra workflow duplicates an existing gate.
In Taproot it would also be a protected workflow change, which forces a
full-CI run.

Taproot's `AGENTS.md` is 32,613 bytes. Appending the block would push it past
the 32,768 bytes Codex reads, and good-agent's `codex/size-budget` rule would
fail.

## Scope

- **`--skip <parts>` (`scripts/trellis-init.mjs`, `src/init.mjs`).** A
  comma-separated list from `ci`, `pr-template`, `playbooks`,
  `branch-protection` and `agents`. A skipped part is neither written nor
  reported as missing. A missing or blank value (for example `--skip
  --force`) and unknown names are usage errors (exit 2), before any
  write. `--dry-run`
  lists what is skipped.
- **good-agent detection.** When the target has `good-agent.config.json`, or
  `.agents/skills/work-task/SKILL.md`, init skips `playbooks` unless
  `--with-playbooks` is passed, and writes the compact block below. With
  `--with-playbooks`, the playbooks are written and the full block is
  used, since its pointers then resolve. `--skip playbooks
  --with-playbooks`, and `--switch-to-local --with-playbooks`, are usage
  errors (exit 2) before any write. A rerun with `--with-playbooks` writes
  only what it is told to, so the owner repeats any other `--skip` flags;
  the help text says so. The output says what it detected and what it
  skipped.
- **Compact AGENTS.md block.** Inside the same `BEGIN/END TRELLIS` markers,
  the block holds:
  - one line naming the backlog root and the config path;
  - the regenerate and check commands;
  - the Loop contract table;
  - one sentence saying that task work follows good-agent's `write-task`,
    `work-task` and `review-loop` skills;
  - one artifact sentence in each mode (committed: the README tables and
    `backlog.json` are generated between markers; local: the index is
    generated into `.generated/`), which TRL0038's switch rewrites.

  The full block stays the default when good-agent is absent. A test pins
  the compact block's size for a ledger plus local config with a short
  `tasksDir`: under 1,200 bytes. Real repos are bounded by the 32,768-byte
  size guard instead, since a long `tasksDir` lengthens the block.
- **Blocks follow what was written and the modes.**
  - When `playbooks` or `branch-protection` is skipped, the full block
    leaves out the lines that point at `trellis/playbooks/` or
    `trellis/branch-protection.md`.
  - Both the full and the compact block, in ledger mode (TRL0037), tell
    AI tools to claim ids with `trellis claim --title`. In local mode
    (TRL0038), they say the index is generated into `.generated/`.
  - When `ci` is skipped, the full block leaves out the lines about the
    `backlog` job gating merges and CI running `check`.
  - Any re-render of an existing TRELLIS block keeps the variant already
    there (full or compact), writes nothing when `--skip agents` is given,
    and passes through the size guard below. TRL0038's `--switch-to-local`
    edits only the artifact sentences, so lines a skip left out stay out.
  - Scope cut (2026-11-19): `--with-playbooks` never rewrites an existing
    TRELLIS block. When one exists, it writes the playbooks, leaves
    AGENTS.md untouched, and prints the full block for the owner to place
    by hand.
- **Init's own output follows the skips.** With `--skip ci`, the
  completion message tells the owner to require `trellis check` through
  their existing CI (SPEC §10), not a `backlog` job that was never created.
  The copied `trellis/branch-protection.md` and its packaged mirror under
  `templates/` say the same: require the status that runs `trellis
  check`, which is the `backlog` job only when Trellis's workflow is
  installed. With `--skip branch-protection`, init leaves out the
  protection recipe link.
- **`pr-draft` without a PR template.** When the `pr-draft` playbook
  exists but `.github/pull_request_template.md` does not (for example
  after `--skip pr-template`), the playbook and the MCP prompt defer to
  the repo's own PR instructions instead of asking to fill a template.
  Repos holding a `pr-draft.md` copied by an older release get the new
  text by rerunning `trellis init --force` on that file, as the release
  notes say. The prompt reads the file as it is.
- **Size guard.** Before writing AGENTS.md, init computes the result's size.
  If it would exceed 32,768 bytes, ordinary scaffolding writes nothing to
  AGENTS.md, prints the block on stdout, says how many bytes it needs, and
  exits 0 with a warning, leaving the placement to the owner. The other
  files are still written. For `--switch-to-local` (TRL0038), an
  over-budget AGENTS.md edit is a preflight failure: it refuses before
  changing the config or staging any removal.
- **MCP prompts without playbooks.** Today `src/prompts.mjs` throws
  `not_found` for the `work-task`, `code-review` and `pr-draft` prompts when
  `trellis/playbooks/` is absent. The fallback applies per prompt,
  whenever that prompt's own playbook file is missing, so a directory
  holding only `code-review.md` still serves `work-task` through it. In
  that case, when good-agent is detected
  (same test as above), the prompt returns a short message naming
  good-agent's `write-task`, `work-task` and `review-loop` skills
  (`work-task` and `code-review`), or `review-loop` and the repo's own PR
  flow (`pr-draft`). The `work-task` fallback still validates the requested
  id, as the prompt does today, and names that id in its handoff.
  Otherwise it says the playbook is absent and points at `trellis init
  --with-playbooks`. Init's output
  says the same when it skips the playbooks.
- **Release.** This story lands last of TRL0037–TRL0040 and bumps
  `package.json` `version` from 0.2.0 to 0.3.0 in its PR, with the matching
  version fields in `package-lock.json`. The merge to main
  then publishes the release (`.github/workflows/release.yml`).
- **Docs.** README "Onboard a repo" and `docs/import.md` describe `--skip`,
  the detection, the size guard and the MCP prompt behavior.

## Acceptance

- `node --test` covers these:
  - Each `--skip` part on its own, an unknown part, and a missing or blank
    value (exit 2, nothing written).
  - Detection through each of the two marker files, and `--with-playbooks`
    overriding it.
  - The compact block's content and its byte ceiling.
  - `--switch-to-local` (TRL0038) on a repo with a compact block rewrites
    its artifact sentences to the `.generated/` wording, leaves no marker
    lines, and stays under 1,200 bytes.
  - The size guard on an AGENTS.md of 32,600 bytes: the file is unchanged
    and the block is printed.
  - Each of the three MCP prompts, with playbooks absent, returns the
    good-agent message when good-agent is detected, and the
    `--with-playbooks` message when it is not.
  - `--skip playbooks,branch-protection` without good-agent writes a full
    block with no path to a skipped file.
  - Both blocks carry the claim and `.generated/` wording under a ledger
    plus local config.
  - `--with-playbooks` on a repo with a compact block writes the playbooks,
    leaves AGENTS.md byte-identical and prints the full block.
  - `--switch-to-local --with-playbooks` is a usage error.
  - `--switch-to-local` on a full block created with `--skip
    ci,branch-protection`, run without repeating those flags, leaves the
    job reference and guide link absent. In both migration tests, the
    `BEGIN/END TRELLIS` delimiters survive and the generated-marker
    references are gone.
  - `--switch-to-local` with an AGENTS.md whose edit would exceed 32,768
    bytes refuses before changing the config.
  - `--skip ci` changes the completion message and the copied
    branch-protection guide to point at the owner's CI status, and `--skip
    branch-protection` drops the recipe link.
  - `pr-draft` with the playbook but no template defers to the repo's PR
    instructions.
  - A playbook directory holding only `code-review.md`, with good-agent
    detected, serves `work-task` through the fallback. A malformed id is
    still rejected, and a valid one appears exactly in the handoff.
  - With no skip flags, no good-agent and an AGENTS.md whose result fits
    the budget, output is byte-identical to the suite as TRL0039 left it,
    except for the intentionally revised `pr-draft.md` and
    `branch-protection.md` copies.
    An oversized AGENTS.md is now left untouched, where init used to
    append.
- `npm run backlog:check` and `node --test` exit 0.

## Notes

- Rejected: removing the playbooks from Trellis. They serve repos without
  good-agent, and the MCP prompts (`src/prompts.mjs`) read them.
- Rejected: shortening the default block. Repos without good-agent need the
  loop pointers it carries.
- TRL0036, on branch `je/trl0036/adopt-good-agent` until merged, adopts
  good-agent in this repo. The playbooks here stay, because
  they are the source that `init` copies and the MCP server serves.

## Risks

- Detection by file presence can misfire on a repo that has good-agent
  installed but does not use its loop. Mitigation: `--with-playbooks`
  restores them, and the output says what was detected.

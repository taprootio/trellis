# TRL0038 — Keep generated backlog artifacts out of git

## Problem

SPEC §8 requires `README.md` (between its markers), `completed/index.md`,
`removed/index.md` and `backlog.json` to be committed, and §8.3 makes
`--check` fail when they are stale. Every branch that adds, edits or closes
a task rewrites those four files, so parallel branches conflict on them
even when they touch different tasks. In Taproot, 83 file changes to the
generated index and `backlog.json` landed in one month.

## Scope

- **Config (SPEC §7).** A new optional key, `generatedArtifacts`, is
  `"committed"` (today's behavior, the default) or `"local"`. Validation
  rejects any other value. The key is added under `specVersion` 2.5, which
  TRL0037 owns. This story merges after TRL0037.
- **Local mode output (SPEC §8, new §8.5).** The generator writes every
  artifact under `<tasksDir>/.generated/`:
  - `index.md`: the milestone tables;
  - `completed.md`;
  - `removed.md`;
  - `backlog.json`, unchanged in shape.

  Local CLI `generate` writes through the shared rollback writer
  (`writeArtifactFiles`), not the existing CLI write loop plus `mkdir`.
  The generator creates `.generated/` when it is missing before writing,
  and removes it again after any rollback when it created the folder and it
  is empty.
  Each Markdown file is wholly generated: it needs no markers and has no
  author-owned text. Links inside the files resolve from `.generated/` (for
  example `../active/<ID>.md` in `index.md`, `../completed/tasks/<ID>.md`
  in `completed.md`, and `../removed/<ID>.md` in `removed.md`).
- **`nextId` in local mode.** Every local-mode writer (`generate`, MCP
  `regenerate`, `init`, and `import`, which runs in scan mode only, since
  TRL0037 refuses it in ledger mode) passes TRL0037's `nextIdOverride`.
  With `idAllocation` `"ledger"`, that is the ledger preview when the ref
  is a valid ledger, otherwise `null`. In scan mode it is the scan
  value. SPEC
  §8 states the exception: a local, uncommitted `backlog.json` may change
  when the ledger changes, even when items and config do not.
- **Author-owned files in local mode.** `<tasksDir>/README.md`,
  `completed/index.md` and `removed/index.md` are author-owned. Generation
  and scaffolding never write them. `check` and MCP `validate` still read
  each one that exists: if it holds one of the exact generated-marker
  comment lines (for example `<!-- BEGIN GENERATED:MILESTONES -->` alone
  on a line), they fail and name the file. Prose that mentions a marker
  does not trip the rule. This catches a half-finished switch.
- **`check` in local mode.** It validates config, roster and items (§8.3
  item 1), runs the marker scan above, and compares no generated file.
  This stays the required CI gate (§10). `generate` writes `.generated/`.
- **Ignore rule is the user's job.** Neither `trellis init` nor
  `--switch-to-local` edits `.gitignore`. Both require the rule to be in
  effect already. Their preflight probes each of the four output paths with
  `git check-ignore -q --no-index -- ./<repo-relative path>` (exit 0 ignored,
  1 not ignored, 128 a git error, which is reported). If any output is not
  ignored, they refuse before writing and print the exact line to add:
  `<tasksDir>/.generated/`, a normalized literal path with every gitignore
  metacharacter (`*?[]!#\` and leading or trailing space) escaped, so
  `tasksDir: "planning[old]"` prints a line that works. Outside a git work
  tree, or without git, the probe is skipped.
  Git discovery has three outcomes. Git absent (ENOENT when spawning it) or
  the directory confirmed outside any work tree: skip the git half. Any
  other discovery failure (ownership or `safe.directory`, permission, an
  unexpected exit): refuse before writing, and report the error.
- **Init in local mode.** When the config already says `"local"`,
  `trellis init` neither creates nor requires `completed/index.md`,
  `removed/index.md` or the README markers. Existing files at those paths
  do not block it. It runs the shared output preflight (see "Shared output
  preflight" below) before scaffolding anything: the marker scan, the
  regular-file check on each existing output path (also outside git) and
  the ignore probe above. It never edits `.gitignore`. The AGENTS.md block
  it writes (`src/init.mjs`) is rendered for the mode: in local mode it says
  the index is generated into the ignored `.generated/` folder, and that no
  committed file under the backlog root is generated. `init --force` with
  an existing local config is refused before any write: it would replace
  the config, fall back to committed mode, and overwrite author-owned
  files.
- **`trellis init --switch-to-local`** is a standalone migration action
  on a repo in either mode. It cannot be combined with `--import` or
  `--retire-source` (usage error, exit 2, before any write). It is
  dispatched and validated in `scripts/trellis-init.mjs` before
  `promptMissing` and the ordinary scaffold path, so it never prompts. It
  never runs `git rm` itself and never edits `.gitignore`.
  - **Preflight.** It runs every check before changing anything, and
    stops naming the file and the fix when any fails:
    - the four output paths are not all ignored (the probe above; it prints
      the line to add);
    - `.generated/` or one of its four output paths is a symlink or the
      wrong type, by the shared filesystem checks (an ignored directory at
      `.generated/index.md` is refused before any edit);
    - a file it would edit or remove (README, index files, AGENTS.md, the
      config) is a symlink or not a regular file. This is checked first,
      before anything is read or snapshotted;
    - a file it would edit or remove has uncommitted changes (so the printed
      plain `git rm` works on a clean file);
    - a removal candidate (a tracked legacy `backlog.json` and a
      generated-only index file) gets the same symlink or regular-file check
      and the same cleanliness check as an edit target, so a dirty tracked
      `backlog.json` is refused before any edit;
    - a marker in `README.md` or an index file is unpaired;
    - an untracked `README.md` or index file holds generated markers;
    - a marker comment shares its line with other text (an inline pair the
      committed-mode generator accepts). The message says to move the
      comment onto its own line;
    - a file holds a marker more than once, nested markers, or a marker
      that belongs to another file (for example a completed marker in
      `README.md`). The committed generator only ever replaced the first
      pair, so later pairs may be authored text, such as a fenced
      example;
    - a file under `<tasksDir>/.generated/` is tracked by git (detected with
      literal `git ls-files`);
    - an untracked `<tasksDir>/backlog.json` exists (the message says to
      inspect it, then remove or move it).
  - **Changes.** Files only.
    - It sets `generatedArtifacts` to `"local"`, and sets `specVersion` to
      2.5 when it is lower. It refuses when the config has load errors
      (item errors do not block it). It writes the config, and checks it for
      uncommitted changes, only when one of those two keys actually needs to
      change. Then it edits only those keys in the parsed config and rewrites
      it with `JSON.stringify(obj, null, 2)` plus a newline, as import does
      for `nextIdFloor`. A config that is already local keeps its bytes, even
      when it is uncommitted, and the switch still strips the markers.
    - In `README.md`, and in each index file that holds authored text, it
      strips the generated block and its markers, keeping authored text.
      An index file is generated-only when it held a verified generated block
      and nothing but Trellis's own skeleton (or blank text). The switch does
      not edit a generated-only file at all. It leaves it byte-for-byte as it
      is, reports it, and prints a removal command for it. A tracked index
      file with no markers and no other content is author-owned: it is kept
      and gets no removal command.
    - In AGENTS.md, it replaces the artifact bullet inside an existing
      TRELLIS block only when the bullet matches the committed-mode text
      exactly, from its first line through its last. Otherwise it leaves
      AGENTS.md untouched and warns. The repo's own Loop contract values
      and any lines init left out are kept. When AGENTS.md has no TRELLIS
      block (for example after `--skip agents`), it leaves AGENTS.md
      untouched.
    - When it finishes, it prints one command for each legacy artifact still
      tracked: `backlog.json`, and each untouched generated-only index file.
      Each is
      shell-quoted, meant to run from the target repo, and has the form
      `git --literal-pathspecs rm -- '<path>'`. It is plain `rm`, not
      `--cached`, and the files are clean, so each one leaves the disk too
      and a rerun or `git add -A` cannot bring it back. The user runs them.
  - **Sequence and recovery.** After preflight the switch runs: snapshot
    every file it edits in memory, apply the edits (README, index files with
    authored text, AGENTS.md, all computed in memory during preflight), write the config
    last, then print the commands. Any failure restores every snapshot, so a
    rerun starts clean (see Refinements).
  - **Pathspecs.** The preflight `git status` and `git ls-files`, and the
    printed removal commands, use `--literal-pathspecs`, so a `tasksDir` such
    as `planning*` cannot match another folder. `git check-ignore` does not
    take it (git exits 128), so the probe is
    `git check-ignore -q --no-index -- ./<path>` only. Preflight runs git
    with `GIT_OPTIONAL_LOCKS=0`, so no index refresh is written.
  - **Behavior.** `--dry-run` lists the edits and the printed commands and
    writes nothing. The action never stages and never commits, and a second
    run changes nothing. In a directory that is not a git repo (or without
    git), it refuses before any change, since its preflight needs git.
- **Shared output preflight.** Every local-mode writer's preflight
  (`generate`, MCP `regenerate`, `create_task`, `move_task`, `import`,
  ordinary `init`) requires each existing output path, and `.generated`
  itself, to be a regular file or real directory as expected (no symlink,
  no wrong type), in scan mode and in ledger mode, with or without git. It
  refuses before any write or claim. Its git discovery follows the three
  outcomes above, so an ambiguous discovery failure refuses instead of
  skipping the git half.
  Ordinary init runs the same filesystem checks before scaffolding, also
  outside git.
- **Migration order for an existing, Trellis-shaped backlog**, documented
  in `docs/import.md` as this story ships it:
  1. Add `<tasksDir>/.generated/` to `.gitignore` (the printed line).
  2. Run `trellis init --switch-to-local`. It sets `"local"` and
     `specVersion` 2.5 itself. It runs before ordinary init, so its
     preflight sees a tracked `.generated/` file before init could
     overwrite it.
  3. Run the removal commands it prints. They delete the untouched
     generated-only index files and the legacy `backlog.json`.
  4. Run `trellis init`, without `--force`.
  5. Run `trellis generate`, then `trellis check`.

  TRL0039 adds the `legacy` key to the config, and TRL0040 adds `--skip` to
  step 4 (ordinary init), each as separate task commits on one branch;
  TRL0037–TRL0040 land in one PR. `--switch-to-local` takes no
  `--skip`.
- **Marker scan before writes.** In local mode, these run the shared
  marker scan before writing anything, and refuse on a leftover marker, so
  none can report success while `check` fails:
  - CLI `trellis generate` and MCP `regenerate`;
  - ordinary `trellis init` (with a local config);
  - `trellis import`;
  - `trellis init --import`, before it calls `applyScaffold`, when the
    target already has a local config;
  - MCP `create_task` and `move_task`, before claiming an id or writing an
    item.
- **Import rollback.** Local-mode `applyImport` writes artifacts through
  the shared local writer (`writeArtifactFiles`), which records every
  directory it creates. On a failure, import removes each recorded
  directory that is empty (such as `.generated/`), and keeps directories
  that already existed. Import records each new item path for rollback as
  soon as it creates it, before it writes the contents (open with `wx`,
  record, then write), so a partial item write is rolled back too. Import also records each directory its item-write
  loop creates (not only those the artifact writer creates), and removes
  them after it rolls back the files, so a config-only target is left as
  it started. The pre-scaffold marker refusal in `init --import`
  goes through the same `ImportRefused` handler (exit 2, target unchanged).
- **One validator.** The local-mode marker rule and the skipped file
  comparison live in one shared validation function in `src/backlog.mjs`.
  Both the `check` CLI and MCP `validateOp` call it, so they cannot
  disagree. It is one shared local validation entry point that returns the
  ordered errors: config, roster, items, then markers. It does not stop at
  item errors, so a malformed item and a stray marker both show.
- **One place for the mode.** One mode-aware set of artifact paths,
  derived once from the config in `src/backlog.mjs`, drives:
  - `generateArtifacts`, for the CLI and `src/mcp.mjs`;
  - `src/import.mjs`, for its "initialized backlog" precondition
    (line ~346), its rollback snapshot (line ~661) and `generatedRels`;
  - `src/init.mjs`, for `markerFiles` and `generatedFiles` (lines ~76-83
    and ~506), the dry-run list and the skip bookkeeping;
  - `artifactPaths` in `src/ledger.mjs`, which feeds
    `refuseSymlinkedArtifacts`.

  In local mode, import's precondition is "config and roster load", since
  the index files do not exist.
- **Consumers.** `src/mcp.mjs` tools already build their results from the
  item files. `regenerate` writes to `.generated/` in local mode, and
  `create_task` and `move_task` call it as today. `src/history.mjs`
  (`history.json`, §8.4) is unchanged.
- **Docs.** SPEC.md §2 (the layout tree notes both modes), §3 (where
  `nextId` comes from), §6.1 (`effortImage` stays relative to `tasksDir`
  in both modes, not to the artifact), §7, §8 (including the local
  `nextId` exception),
  §10 and §11 (conformance names the
  generated artifacts per mode).
  README "Onboard a repo" mentions the mode. The playbooks
  `trellis/playbooks/conventions.md` and `trellis/playbooks/code-review.md`,
  and their packaged mirrors under `templates/trellis/playbooks/`, say what
  `check` verifies in each mode. Committed mode: validation plus
  generated-file freshness. Local mode: validation and the marker scan only,
  with `.generated/` produced by `generate`. TRL0035's migration steps follow
  the revised sequence.

## Notes

- Owner decision 2026-11-19: stop committing the generated index and
  `backlog.json`. Readers browse with the local viewer (TRL0005, TRL0041) instead of
  the committed tables.
- Rejected: keeping the paths and adding them to `.gitignore`. `README.md`
  mixes author prose with the generated tables, so it cannot be ignored,
  and the index files may also hold author text outside their markers.
- Rejected: a git merge driver that regenerates on conflict. It needs
  per-clone setup (`git config merge.<driver>`), and it still churns every
  diff.

## Risks

- A repo that publishes the committed README tables, for example on its
  forge's file view, loses them. Mitigation: the mode is opt-in, and the
  SPEC entry says what is given up.
- A consumer that reads the committed `backlog.json` from the default branch
  breaks. Mitigation: the SPEC entry tells consumers to run `trellis
  generate`, or the MCP `list_tasks` tool, instead.

## Refinements

Decisions taken at plan time (2026-11-20). Each carried review finding was
checked against the code. TRL0037 is the foundation (complete at 7bb37bc).
Threat model, as in SPEC §3.1: cooperating writers and trusted config.
Hostile layouts are refused, not handled.

Foundation from TRL0037 that this task reuses unchanged:
`nextIdOverride` is an options object, `{ nextIdOverride }`, on
`buildBacklogJson` and `generateArtifacts`, and `undefined` means the scan
value while `null` is emitted as `null`. `ledgerMarkerRe` is the
whole-line marker matcher. Ledger mode fills markers literally.
`writeArtifactsStaged` and `refuseSymlinkedArtifacts` write and guard
artifacts in ledger mode. `check` never calls git. Scan mode and committed
mode stay byte-for-byte unchanged.

Stale assumptions in the story, checked against the code:

- Line numbers moved: import's precondition is `src/import.mjs:346` and its
  rollback snapshot is `:661`. In `src/init.mjs`, `markerFiles` and
  `generatedFiles` are at `:76-83`, and the generated set is read at `:506`.
  `artifactPaths` in `src/ledger.mjs:651` is a fifth copy of the four
  committed paths, so it joins the single mode-aware set. Scope is
  corrected above.
- `scripts/backlog-readme.mjs` does not call `validateOp`. It runs
  `readBacklog`, then `generateArtifacts`, then compares files. The shared

Design decisions:

- **One mode-aware set of paths.** `artifactSet(repoRoot, cfg)` in
  `src/backlog.mjs` returns the generated files with their mode, and the
  author-owned files to scan. Each entry carries both its absolute and its
  repo-relative path. Local mode names `index.md`, `completed.md`,
  `removed.md` and `backlog.json` under `.generated/`. `paths()` keeps its
  keys, and `history.json` is unchanged. Every consumer listed in Scope
  reads this set. No code outside it spells an artifact path.
- **Local files carry no markers.** Each Markdown file starts with a
  `# Backlog`, `# Completed tasks` or `# Removed tasks` heading and one
  line saying it is generated and ignored by git. The text is a pure
  function of the items, so it stays deterministic.
- **One validator.** `checkGenerated(repoRoot, cfg, data)` in
  `src/backlog.mjs` returns `{ errors, files }`. In committed mode it
  returns the generator's marker errors and the files to compare. In local
  mode it returns the marker-line errors and no files. A shared local
  validation entry point wraps it and returns ordered errors (config, roster,
  items, markers) with no early exit on item errors. CLI `check` and MCP
  `validateOp` both call that entry point, so they cannot disagree.
- **Marker rule.** A file fails when a line equals one of the six marker
  comments, ignoring trailing spaces, tabs and `\r`. Text that merely
  mentions a marker passes.
- **Git-using helpers live in `src/local-output.mjs`**, not the core:
  `outputPreflight` (marker scan, regular-file checks, then the git half above),
  `previewNextId(repoRoot, cfg)` (the ledger preview in local ledger mode,
  otherwise `undefined`; its result feeds the `nextIdOverride` option), `writeArtifactFiles` (makes `.generated/`, then
  writes), and `ignoreLineFor(tasksDir)`. Init and the switch share
  `ignoreLineFor`, which only formats the line to print, and one
  output-path verifier. The verifier runs `git check-ignore -q --no-index`
  and treats exit 1 as not ignored and exit 128 as a git error to report.
- **Real `.generated/` with a bad output.** Each entry point refuses an
  output that is a symlink or a directory inside a real `.generated/` before
  any write or claim, and a test covers each.
- **`.generated/` itself.** `outputPreflight` refuses a `.generated` that is
  a symlink or not a directory, and any existing output path that is not a
  regular file, in scan and ledger mode, since `refuseSymlinkedArtifacts` only
  inspects the files. Scan mode writes in place; ledger mode uses
  `writeArtifactsStaged` as in TRL0037. In step 4 it is changed to create
  `.generated/` before staging (a shared helper with `writeArtifactFiles`
  is fine) and to remove it after any rollback when it created the folder
  and it is empty.
  It keeps the `hooks.afterArtifactRename` seam.
- **Ordinary init in local mode** does not create README or index files at
  all, since they are author-owned. It skips the marker-order preflight and
  runs, in order: the shared output preflight (marker scan, regular-file
  checks also outside git, the four-path ignore probe, tracked-output
  refusal), then the writes. It never edits `.gitignore`. Its local render
  passes `previewNextId` as `{ nextIdOverride }`. `init --force` and
  `--switch-to-local` check the config through a sibling of
  `assertNotLedgerMode` in `src/import.mjs`.
- **`--switch-to-local` takes only `--dry-run`, `-h` and the target.** Any
  other flag is a usage error (exit 2, before any write), which covers
  `--import`, `--retire-source` and `--force`. It runs in a new
  `src/switch-local.mjs` so `src/init.mjs` does not grow a second job.
- **AGENTS.md in the switch.** One renderer owns the artifact bullet for
  each mode, and `src/init.mjs` exports it so TRL0040's compact block can
  reuse it. The switch replaces the bullet only when the existing text
  matches the committed-mode bullet exactly, from its first line through
  its last. Otherwise it leaves AGENTS.md untouched and prints a warning
  naming the sentence to edit by hand. Reason: an exact match proves the
  bullet is still Trellis's text, so a hand-edited bullet is never
  overwritten, and no parser is needed. This also keeps the repo's Loop
  values.
- **Skeleton-only detection.** An index file is generated-only only when it
  held a verified generated block and, after the block is stripped, equals
  the skeleton's heading and blurb from `src/init.mjs` (exported from there)
  or is blank. It is not edited: it is reported, and its removal command is printed when it
  is tracked. A tracked, markerless, blank index never held a generated block,
  so it is author-owned and gets no command. Anything else is authored and
  kept.
- **Imports in local mode** run in scan mode only, as TRL0037 requires.
  `trellis import` and `init --import` refuse with `ImportRefused`
  (exit 2, `invalid_request` in MCP) on a leftover marker; the
  `init --import` refusal runs before it scaffolds, through the same
  handler, and leaves the target unchanged.
- **Local-mode `backlog.json` `nextId`.** SPEC §8.5 says an uncommitted file
  may differ per clone. CI never reads it.
- **No version bump.** This is part of the unreleased 2.5. TRL0040 carries
  the 0.3.0 bump on the same branch, so `package.json` is untouched here.
- **Reference surfaces.** `scripts/trellis-import.mjs` for flags and exit
  codes, `scripts/trellis-history.mjs` for a git-backed command, and
  TRL0037's `src/ledger.mjs` for the git helper and error class.

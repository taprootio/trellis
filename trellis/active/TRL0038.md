# TRL0038 — Keep generated backlog artifacts out of git

## Problem

SPEC §8 requires `README.md` (between its markers), `completed/index.md`,
`removed/index.md` and `backlog.json` to be committed, and §8.3 makes
`--check` fail when they are stale. Every branch that adds, edits or closes
a task rewrites those four files, so parallel branches conflict on them
even when they touch different tasks. In Taproot, 83 file changes to the
generated index and `backlog.json` landed in one month.

## Scope

- **Config (SPEC §7).** A new optional key, `generatedArtifacts`, is
  `"committed"` (today's behavior, the default) or `"local"`. Validation
  rejects any other value. This ships in the same spec minor as TRL0037 if
  both land together, otherwise its own additive bump.
- **Local mode output (SPEC §8, new §8.5).** The generator writes every
  artifact under `<tasksDir>/.generated/`:
  - `index.md`: the milestone tables;
  - `completed.md`;
  - `removed.md`;
  - `backlog.json`, unchanged in shape.

  Each Markdown file is wholly generated: it needs no markers and has no
  author-owned text. Links inside the files resolve from `.generated/` (for
  example `../active/<ID>.md`).
- **Author-owned files in local mode.** `<tasksDir>/README.md` is
  author-owned and is not touched. `completed/index.md` and
  `removed/index.md` are not read or written. If any of the three still
  holds a `BEGIN GENERATED` marker, `check` fails and the message names the
  file. That catches a half-finished switch.
- **`check` in local mode.** It validates config, roster and items (§8.3
  item 1) and compares no file. This stays the required CI gate (§10).
  `generate` writes `.generated/`.
- **Init in local mode.** When the config already says `"local"`,
  `trellis init` neither creates nor requires `completed/index.md`,
  `removed/index.md` or the README markers. Existing files at those paths,
  with or without markers, do not block it. It adds `<tasksDir>/.generated/`
  to the repo's `.gitignore` when the line is missing.
- **`trellis init --switch-to-local`** works on a repo in either mode:
  - it sets `generatedArtifacts` to `"local"`;
  - it adds the ignore line;
  - it strips any generated block and its markers from `README.md`;
  - it stages `git rm` of `completed/index.md`, `removed/index.md` and
    `backlog.json` where they are tracked.

  It never commits, and a second run changes nothing.
- **Migration order for an existing, Trellis-shaped backlog** (Taproot's
  case), documented in `docs/import.md`:
  1. Write `trellis/backlog.config.json` with `"local"` (and
     `legacyThrough`, TRL0039).
  2. Run `trellis init --skip …`.
  3. Run `trellis init --switch-to-local`.
  4. Run `trellis generate`, then `trellis check`.
- **Consumers.** `src/mcp.mjs` tools already build their results from the
  item files. `regenerate` writes to `.generated/` in local mode, and
  `create_task` and `move_task` call it as today. `src/history.mjs`
  (`history.json`, §8.4) is unchanged.
- **Docs.** SPEC.md §2 (the layout tree notes both modes), §7, §8 and §10.
  README "Onboard a repo" mentions the mode.

## Acceptance

- `node --test` covers each of these in a temporary repo:
  - In local mode, `generate` writes the four files under `.generated/` and
    leaves `README.md` byte-identical.
  - `check` passes with no `.generated/` folder present, as in CI.
  - `check` fails when `README.md` still holds a marker.
  - `--switch-to-local` is idempotent and adds the ignore line once.
  - The migration order above, on a fixture with hand-written unmarked
    index files and a README with markers, ends with `check` passing and
    the three files staged for removal.
  - Committed mode output is byte-identical to before; the existing tests
    pass untouched.
- `npm run backlog:check` and `node --test` exit 0.

## Notes

- Owner decision 2026-11-19: stop committing the generated index and
  `backlog.json`. Readers browse with the local viewer (TRL0005) instead of
  the committed tables.
- Rejected: keeping the paths and adding them to `.gitignore`. `README.md`
  mixes author prose with the generated tables, so it cannot be ignored,
  and the index files may also hold author text outside their markers.
- Rejected: a git merge driver that regenerates on conflict. It needs
  per-clone setup (`git config merge.<driver>`), and it still churns every
  diff.

## Risks

- A repo that publishes the committed README tables, for example on its
  forge's file view, loses them. Mitigation: the mode is opt-in, and the
  SPEC entry says what is given up.
- A consumer that reads the committed `backlog.json` from the default branch
  breaks. Mitigation: the SPEC entry tells consumers to run `trellis
  generate`, or the MCP `list_tasks` tool, instead.

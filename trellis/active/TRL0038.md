# TRL0038 — Keep generated backlog artifacts out of git

## Problem

SPEC §8 requires `README.md` (between its markers), `completed/index.md`,
`removed/index.md` and `backlog.json` to be committed, and §8.3 makes
`--check` fail when they are stale. Every branch that adds, edits or closes
a task rewrites those four files, so parallel branches conflict on them
even when they touch different tasks. In Taproot, 83 file changes to the
generated index and `backlog.json` landed in one month.

## Scope

- **Config (SPEC §7).** A new optional key, `generatedArtifacts`, is
  `"committed"` (today's behavior, the default) or `"local"`. Validation
  rejects any other value. The key is added under `specVersion` 2.5, which
  TRL0037 owns. This story merges after TRL0037.
- **Local mode output (SPEC §8, new §8.5).** The generator writes every
  artifact under `<tasksDir>/.generated/`:
  - `index.md`: the milestone tables;
  - `completed.md`;
  - `removed.md`;
  - `backlog.json`, unchanged in shape.

  The generator creates `.generated/` when it is missing before writing.
  Each Markdown file is wholly generated: it needs no markers and has no
  author-owned text. Links inside the files resolve from `.generated/` (for
  example `../active/<ID>.md` in `index.md`, `../completed/tasks/<ID>.md`
  in `completed.md`, and `../removed/<ID>.md` in `removed.md`).
- **`nextId` in local mode.** Every local-mode writer (`generate`, MCP
  `regenerate`, `init`, `import`) passes TRL0037's `nextIdOverride`. With
  `idAllocation` `"ledger"`, that is the ledger preview when the ref is a
  valid ledger, otherwise `null`. In scan mode it is the scan value. SPEC
  §8 states the exception: a local, uncommitted `backlog.json` may change
  when the ledger changes, even when items and config do not.
- **Author-owned files in local mode.** `<tasksDir>/README.md`,
  `completed/index.md` and `removed/index.md` are author-owned. Generation
  and scaffolding never write them. `check` and MCP `validate` still read
  each one that exists: if it holds one of the exact generated-marker
  comment lines (for example `<!-- BEGIN GENERATED:MILESTONES -->` alone
  on a line), they fail and name the file. Prose that mentions a marker
  does not trip the rule. This catches a half-finished switch.
- **`check` in local mode.** It validates config, roster and items (§8.3
  item 1), runs the marker scan above, and compares no generated file.
  This stays the required CI gate (§10). `generate` writes `.generated/`.
- **Init in local mode.** When the config already says `"local"`,
  `trellis init` neither creates nor requires `completed/index.md`,
  `removed/index.md` or the README markers. Existing files at those paths
  do not block it. It adds `<tasksDir>/.generated/` to the repo's
  `.gitignore` when the line is missing. The AGENTS.md block it writes
  (`src/init.mjs`) is rendered for the mode: in local mode it says the
  index is generated into the ignored `.generated/` folder, and that no
  committed file under the backlog root is generated. `init --force` with
  an existing local config is refused before any write: it would replace
  the config, fall back to committed mode, and overwrite author-owned
  files.
- **`trellis init --switch-to-local`** is a standalone migration action
  on a repo in either mode. It cannot be combined with `--import` or
  `--retire-source` (usage error, exit 2, before any write).
  - **Preflight.** It runs every check before changing anything, and
    stops naming the file and the fix when any fails:
    - a file to be removed has uncommitted changes (no `git rm -f`);
    - a marker in `README.md` or an index file is unpaired;
    - an untracked index file holds generated markers;
    - a file under `<tasksDir>/.generated/` is tracked by git.
  - **Changes.**
    - It sets `generatedArtifacts` to `"local"`, and sets `specVersion` to
      2.5 when it is lower.
    - It adds the ignore line.
    - In `README.md`, `completed/index.md` and `removed/index.md`, it
      strips each generated block and its markers, keeping authored text.
      A file that held only a generated block and boilerplate from
      Trellis's own skeleton is removed with a staged `git rm`. A file with
      authored text is kept. `backlog.json` is removed with `git rm` when
      tracked.
    - In AGENTS.md, it updates only the artifact sentences inside an
      existing TRELLIS block (the generated-file and regenerate wording),
      keeping the repo's own Loop contract values and any lines init
      left out. When AGENTS.md has no TRELLIS block (for example after
      `--skip agents`), it leaves AGENTS.md untouched.
  - **Behavior.** `--dry-run` lists every change and writes and stages
    nothing. The action never commits, and a second run changes nothing.
- **Migration order for an existing, Trellis-shaped backlog**, documented
  in `docs/import.md` as this story ships it:
  1. Write `trellis/backlog.config.json` with `"local"` and `specVersion`
     2.5.
  2. Run `trellis init`, without `--force`.
  3. Run `trellis init --switch-to-local`.
  4. Run `trellis generate`, then `trellis check`.

  TRL0039 adds the `legacy` key to step 1, and TRL0040 adds `--skip` to
  step 2, each in its own PR.
- **Import precondition.** In local mode, `trellis import` runs the
  shared marker scan before writing anything, and refuses on a leftover
  marker, so it cannot report success while `check` fails.
- **One validator.** The local-mode marker rule and the skipped file
  comparison live in one shared validation function in `src/backlog.mjs`.
  Both the `check` CLI and MCP `validateOp` call it, so they cannot
  disagree.
- **One place for the mode.** One mode-aware set of artifact paths,
  derived once from the config in `src/backlog.mjs`, drives:
  - `generateArtifacts`, for the CLI and `src/mcp.mjs`;
  - `src/import.mjs`, for its "initialized backlog" precondition
    (line ~309), its rollback snapshot (line ~623) and `generatedRels`;
  - `src/init.mjs`, for `markerFiles` and `generatedFiles` (lines ~77-85
    and ~553), the dry-run list and the skip bookkeeping.

  In local mode, import's precondition is "config and roster load", since
  the index files do not exist.
- **Consumers.** `src/mcp.mjs` tools already build their results from the
  item files. `regenerate` writes to `.generated/` in local mode, and
  `create_task` and `move_task` call it as today. `src/history.mjs`
  (`history.json`, §8.4) is unchanged.
- **Docs.** SPEC.md §2 (the layout tree notes both modes), §3 (where
  `nextId` comes from), §7, §8 (including the local `nextId` exception),
  §10 and §11 (conformance names the
  generated artifacts per mode).
  README "Onboard a repo" mentions the mode.

## Acceptance

- `node --test` covers each of these in a temporary repo:
  - In local mode, `generate` writes the four files under `.generated/` and
    leaves `README.md` byte-identical.
  - `check` passes with no `.generated/` folder present, as in CI.
  - `check` fails when `README.md` still holds a marker.
  - `--switch-to-local` is idempotent and adds the ignore line once.
  - The migration order above, on a fixture with a hand-written unmarked
    `completed/index.md` (kept as is), a generated-only `removed/index.md`
    (staged for removal) and a README with markers (block stripped, prose
    kept), ends with `check` passing. The fixture's `.generated/` files are
    ignored by git.
  - The AGENTS.md block in local mode names `.generated/` and mentions no
    markers.
  - The links in `completed.md` and `removed.md` resolve.
  - After `--switch-to-local` on a committed-mode repo whose TRELLIS block
    has a customized `gates` row, AGENTS.md names `.generated/`, holds no
    generated-marker lines, and keeps the customized row.
  - `--switch-to-local --dry-run` writes and stages nothing, and
    `--switch-to-local --import x` is a usage error.
  - The switch refuses, unchanged, on an unpaired README marker, on an
    untracked index file with markers, and on a tracked `.generated/`
    file.
  - The switch raises a 2.4 config to 2.5.
  - `init --force` on a local-mode repo is refused before any write.
  - In local ledger mode, `.generated/backlog.json` holds the ledger
    preview with the ref present, and `null` without it, after both
    `init` and `generate`.
  - `import` on a local-mode repo with a leftover README marker refuses,
    and the target is unchanged.
  - MCP `validate` reports the same errors as `check` in local mode,
    including a stray marker line.
  - `--switch-to-local` on a repo with no TRELLIS block leaves AGENTS.md
    byte-identical.
  - `--switch-to-local` with a dirty index file stops, changes nothing and
    names the file.
  - `trellis import --apply` on a local-mode repo writes `.generated/`,
    writes no committed index, and leaves `check` passing.
  - Committed-mode output is byte-identical to the suite as TRL0037 left
    it.
- `npm run backlog:check` and `node --test` exit 0.

## Notes

- Owner decision 2026-11-19: stop committing the generated index and
  `backlog.json`. Readers browse with the local viewer (TRL0005, TRL0041) instead of
  the committed tables.
- Rejected: keeping the paths and adding them to `.gitignore`. `README.md`
  mixes author prose with the generated tables, so it cannot be ignored,
  and the index files may also hold author text outside their markers.
- Rejected: a git merge driver that regenerates on conflict. It needs
  per-clone setup (`git config merge.<driver>`), and it still churns every
  diff.

## Risks

- A repo that publishes the committed README tables, for example on its
  forge's file view, loses them. Mitigation: the mode is opt-in, and the
  SPEC entry says what is given up.
- A consumer that reads the committed `backlog.json` from the default branch
  breaks. Mitigation: the SPEC entry tells consumers to run `trellis
  generate`, or the MCP `list_tasks` tool, instead.

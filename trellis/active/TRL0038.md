# TRL0038 — Keep generated backlog artifacts out of git

## Problem

SPEC §8 requires `README.md` (between its markers), `completed/index.md`,
`removed/index.md` and `backlog.json` to be committed, and §8.3 makes
`--check` fail when they are stale. Every branch that adds, edits or closes
a task rewrites those four files, so parallel branches conflict on them
even when they touch different tasks. In Taproot, 83 file changes to the
generated index and `backlog.json` landed in one month.

## Scope

- **Config (SPEC §7).** A new optional key, `generatedArtifacts`, is
  `"committed"` (today's behavior, the default) or `"local"`. Validation
  rejects any other value. The key is added under `specVersion` 2.5, which
  TRL0037 owns. This story merges after TRL0037.
- **Local mode output (SPEC §8, new §8.5).** The generator writes every
  artifact under `<tasksDir>/.generated/`:
  - `index.md`: the milestone tables;
  - `completed.md`;
  - `removed.md`;
  - `backlog.json`, unchanged in shape.

  The generator creates `.generated/` when it is missing before writing.
  Each Markdown file is wholly generated: it needs no markers and has no
  author-owned text. Links inside the files resolve from `.generated/` (for
  example `../active/<ID>.md` in `index.md`, `../completed/tasks/<ID>.md`
  in `completed.md`, and `../removed/<ID>.md` in `removed.md`).
- **`nextId` in local mode.** Every local-mode writer (`generate`, MCP
  `regenerate`, `init`, and `import`, which runs in scan mode only, since
  TRL0037 refuses it in ledger mode) passes TRL0037's `nextIdOverride`.
  With `idAllocation` `"ledger"`, that is the ledger preview when the ref
  is a valid ledger, otherwise `null`. In scan mode it is the scan
  value. SPEC
  §8 states the exception: a local, uncommitted `backlog.json` may change
  when the ledger changes, even when items and config do not.
- **Author-owned files in local mode.** `<tasksDir>/README.md`,
  `completed/index.md` and `removed/index.md` are author-owned. Generation
  and scaffolding never write them. `check` and MCP `validate` still read
  each one that exists: if it holds one of the exact generated-marker
  comment lines (for example `<!-- BEGIN GENERATED:MILESTONES -->` alone
  on a line), they fail and name the file. Prose that mentions a marker
  does not trip the rule. This catches a half-finished switch.
- **`check` in local mode.** It validates config, roster and items (§8.3
  item 1), runs the marker scan above, and compares no generated file.
  This stays the required CI gate (§10). `generate` writes `.generated/`.
- **Init in local mode.** When the config already says `"local"`,
  `trellis init` neither creates nor requires `completed/index.md`,
  `removed/index.md` or the README markers. Existing files at those paths
  do not block it. It adds an ignore line for `<tasksDir>/.generated/` to
  the repo's `.gitignore` when one is missing. The line is a normalized
  literal path, with every gitignore metacharacter (`*?[]!#\` and leading
  or trailing space) escaped, so `tasksDir: "planning[old]"` is ignored
  correctly. Init then confirms with `git check-ignore` that each of the
  four real output paths is ignored (see "Output precondition" in
  Refinements), and fails if any is not. The AGENTS.md block it writes
  (`src/init.mjs`) is rendered for the mode: in local mode it says the
  index is generated into the ignored `.generated/` folder, and that no
  committed file under the backlog root is generated. `init --force` with
  an existing local config is refused before any write: it would replace
  the config, fall back to committed mode, and overwrite author-owned
  files.
- **`trellis init --switch-to-local`** is a standalone migration action
  on a repo in either mode. It cannot be combined with `--import` or
  `--retire-source` (usage error, exit 2, before any write).
  - **Preflight.** It runs every check before changing anything, and
    stops naming the file and the fix when any fails:
    - a file to be removed has uncommitted changes (no `git rm -f`);
    - a marker in `README.md` or an index file is unpaired;
    - an untracked `README.md` or index file holds generated markers or
      would be removed (it cannot be `git rm`'d);
    - a marker comment shares its line with other text (an inline pair the
      committed-mode generator accepts). The message says to move the
      comment onto its own line;
    - a file holds a marker more than once, nested markers, or a marker
      that belongs to another file (for example a completed marker in
      `README.md`). The committed generator only ever replaced the first
      pair, so later pairs may be authored text, such as a fenced
      example;
    - a file under `<tasksDir>/.generated/` is tracked by git;
    - an untracked `<tasksDir>/backlog.json` exists (it cannot be `git rm`'d;
      the message says to inspect it, then remove or move it).
  - **Changes.**
    - It sets `generatedArtifacts` to `"local"`, and sets `specVersion` to
      2.5 when it is lower.
    - It adds the ignore line.
    - In `README.md`, `completed/index.md` and `removed/index.md`, it
      strips each generated block and its markers, keeping authored text.
      A file that held only a generated block and boilerplate from
      Trellis's own skeleton is removed with a staged `git rm`. A file with
      authored text is kept. `backlog.json` is removed with `git rm` when
      tracked.
    - In AGENTS.md, it updates only the artifact sentences inside an
      existing TRELLIS block (the generated-file and regenerate wording),
      keeping the repo's own Loop contract values and any lines init
      left out. When AGENTS.md has no TRELLIS block (for example after
      `--skip agents`), it leaves AGENTS.md untouched.
  - **Recovery.** After preflight, the switch edits files from in-memory
    snapshots and runs one `git rm` for every removal as the last step. Any
    failure restores every edited file from its snapshot and leaves nothing
    staged, so a rerun starts clean (see Refinements).
  - **Pathspecs.** Every git call that names a path (preflight status,
    `git rm`, `git check-ignore`) passes it with `--literal-pathspecs`
    (or a `:(literal)` prefix), so a `tasksDir` such as `planning*`
    cannot match another folder.
  - **Behavior.** `--dry-run` lists every change and writes and stages
    nothing. The action never commits, and a second run changes nothing.
    In a directory that is not a git repo (or without git), it refuses
    before any change, since its preflight and removals need git.
- **Migration order for an existing, Trellis-shaped backlog**, documented
  in `docs/import.md` as this story ships it:
  1. Write `trellis/backlog.config.json` with `"local"` and `specVersion`
     2.5.
  2. Run `trellis init --switch-to-local`. It runs before ordinary init, so
     its preflight sees a tracked `.generated/` file before init could
     overwrite it.
  3. Run `trellis init`, without `--force`.
  4. Run `trellis generate`, then `trellis check`.

  TRL0039 adds the `legacy` key to step 1, and TRL0040 adds `--skip` to
  step 3 (ordinary init), each in its own PR. `--switch-to-local` takes no
  `--skip`.
- **Marker scan before writes.** In local mode, these run the shared
  marker scan before writing anything, and refuse on a leftover marker, so
  none can report success while `check` fails:
  - CLI `trellis generate` and MCP `regenerate`;
  - ordinary `trellis init` (with a local config);
  - `trellis import`;
  - `trellis init --import`, before it scaffolds, when the target already
    has a local config;
  - MCP `create_task` and `move_task`, before claiming an id or writing an
    item.
- **Import rollback.** On a failure, local-mode import also removes any
  empty directory it created (such as `.generated/`), and keeps
  directories that already existed.
- **One validator.** The local-mode marker rule and the skipped file
  comparison live in one shared validation function in `src/backlog.mjs`.
  Both the `check` CLI and MCP `validateOp` call it, so they cannot
  disagree.
- **One place for the mode.** One mode-aware set of artifact paths,
  derived once from the config in `src/backlog.mjs`, drives:
  - `generateArtifacts`, for the CLI and `src/mcp.mjs`;
  - `src/import.mjs`, for its "initialized backlog" precondition
    (line ~346), its rollback snapshot (line ~661) and `generatedRels`;
  - `src/init.mjs`, for `markerFiles` and `generatedFiles` (lines ~76-83
    and ~506), the dry-run list and the skip bookkeeping;
  - `artifactPaths` in `src/ledger.mjs`, which feeds
    `refuseSymlinkedArtifacts`.

  In local mode, import's precondition is "config and roster load", since
  the index files do not exist.
- **Consumers.** `src/mcp.mjs` tools already build their results from the
  item files. `regenerate` writes to `.generated/` in local mode, and
  `create_task` and `move_task` call it as today. `src/history.mjs`
  (`history.json`, §8.4) is unchanged.
- **Docs.** SPEC.md §2 (the layout tree notes both modes), §3 (where
  `nextId` comes from), §6.1 (`effortImage` stays relative to `tasksDir`
  in both modes, not to the artifact), §7, §8 (including the local
  `nextId` exception),
  §10 and §11 (conformance names the
  generated artifacts per mode).
  README "Onboard a repo" mentions the mode.

## Acceptance

- `node --test` covers each of these in a temporary repo:
  - In local mode, `generate` writes the four files under `.generated/` and
    leaves `README.md` byte-identical.
  - `check` passes with no `.generated/` folder present, as in CI.
  - `check` fails when `README.md` still holds a marker.
  - `--switch-to-local` is idempotent and adds the ignore line once.
  - The migration order above (switch, then init), on a fixture with a hand-written unmarked
    `completed/index.md` (kept as is), a generated-only `removed/index.md`
    (staged for removal) and a README with markers (block stripped, prose
    kept), ends with `check` passing. The fixture's `.generated/` files are
    ignored by git.
  - The AGENTS.md block in local mode names `.generated/` and mentions no
    markers.
  - The links in `completed.md` and `removed.md` resolve.
  - After `--switch-to-local` on a committed-mode repo whose TRELLIS block
    has a customized `gates` row, AGENTS.md names `.generated/`, holds no
    generated-marker lines, and keeps the customized row.
  - `--switch-to-local --dry-run` writes and stages nothing, and
    `--switch-to-local --import x` is a usage error.
  - The switch refuses, unchanged, on an unpaired README marker, an
    inline marker pair, an untracked README or index file with markers,
    and a tracked `.generated/` file.
  - With `tasksDir: "planning[old]"`, `.generated/` outputs are ignored
    (`git check-ignore`). With `tasksDir: "planning*"` and a tracked
    `planning-old/backlog.json`, the switch leaves that file staged as
    is.
  - A README with a second marker pair inside a fenced example makes the
    switch refuse, unchanged.
  - MCP `create_task` on a repo with a leftover marker refuses without
    claiming or writing.
  - A failed first local import leaves no new `.generated/` directory.
  - The switch raises a 2.4 config to 2.5.
  - `init --force` on a local-mode repo is refused before any write.
  - In local ledger mode, `.generated/backlog.json` holds the ledger
    preview with the ref present, and `null` without it, after both
    `init` and `generate`.
  - `import` on a local-mode repo with a leftover README marker refuses,
    and the target is unchanged.
  - MCP `validate` reports the same errors as `check` in local mode,
    including a stray marker line.
  - `--switch-to-local` on a repo with no TRELLIS block leaves AGENTS.md
    byte-identical.
  - `--switch-to-local` with a dirty index file stops, changes nothing and
    names the file.
  - `trellis import --apply` on a local-mode repo writes `.generated/`,
    writes no committed index, and leaves `check` passing.
  - Committed-mode output is byte-identical to the suite as TRL0037 left
    it.
- `node --test` also covers each of these (added at plan time):
  - Every local-mode writer refuses on an output path that is not ignored
    or is tracked, inside a git work tree, and skips that check outside
    one: CLI `generate`, MCP `regenerate`, `create_task` and `move_task`,
    `import` and ordinary `init`. `check` never runs git.
  - CLI `generate`, MCP `regenerate` and ordinary `init` refuse on a
    leftover marker and write nothing.
  - The switch refuses on an untracked `<tasksDir>/backlog.json`, and a
    failed `git rm` leaves every edited file restored and nothing staged.
  - `init` and the switch each verify the four real output paths are
    ignored, and fail when a user's own `.gitignore` negates the line.
  - A local-mode `.generated` that is a symlink or a file is refused in
    ledger mode.
- `npm run backlog:check` and `node --test` exit 0.

## Notes

- Owner decision 2026-11-19: stop committing the generated index and
  `backlog.json`. Readers browse with the local viewer (TRL0005, TRL0041) instead of
  the committed tables.
- Rejected: keeping the paths and adding them to `.gitignore`. `README.md`
  mixes author prose with the generated tables, so it cannot be ignored,
  and the index files may also hold author text outside their markers.
- Rejected: a git merge driver that regenerates on conflict. It needs
  per-clone setup (`git config merge.<driver>`), and it still churns every
  diff.

## Risks

- A repo that publishes the committed README tables, for example on its
  forge's file view, loses them. Mitigation: the mode is opt-in, and the
  SPEC entry says what is given up.
- A consumer that reads the committed `backlog.json` from the default branch
  breaks. Mitigation: the SPEC entry tells consumers to run `trellis
  generate`, or the MCP `list_tasks` tool, instead.

## Refinements

Decisions taken at plan time (2026-11-20). Each carried review finding was
checked against the code. TRL0037 is the foundation (complete at 7bb37bc).
Threat model, as in SPEC §3.1: cooperating writers and trusted config.
Hostile layouts are refused, not handled.

Foundation from TRL0037 that this task reuses unchanged:
`nextIdOverride` is an options object, `{ nextIdOverride }`, on
`buildBacklogJson` and `generateArtifacts`, and `undefined` means the scan
value while `null` is emitted as `null`. `ledgerMarkerRe` is the
whole-line marker matcher. Ledger mode fills markers literally.
`writeArtifactsStaged` and `refuseSymlinkedArtifacts` write and guard
artifacts in ledger mode. `check` never calls git. Scan mode and committed
mode stay byte-for-byte unchanged.

Stale assumptions in the story, checked against the code:

- Line numbers moved: import's precondition is `src/import.mjs:346` and its
  rollback snapshot is `:661`. In `src/init.mjs`, `markerFiles` and
  `generatedFiles` are at `:76-83`, and the generated set is read at `:506`.
  `artifactPaths` in `src/ledger.mjs:651` is a fifth copy of the four
  committed paths, so it joins the single mode-aware set. Scope is
  corrected above.
- `scripts/backlog-readme.mjs` does not call `validateOp`. It runs
  `readBacklog`, then `generateArtifacts`, then compares files. The shared
  validator below is new to both callers.
- Today `generateArtifacts` reports a missing marker as a generate error.
  That is right for committed mode and does not apply in local mode, where
  it reads no file.
- `fillMarkers` and the table builders hard-code the links `active/`,
  `tasks/` and `<ID>.md`. Local mode needs `../`-prefixed links, so the
  builders take a link prefix whose committed default is today's text.

Carried findings, each confirmed against the code:

- **Verify the four real output paths are ignored (init and switch).**
  Accepted. One ignore line covers `.generated/`, but only a
  `git check-ignore` on `index.md`, `completed.md`, `removed.md` and
  `backlog.json` proves it, including against a user `.gitignore` that
  negates the line. This replaces the story's single probe path.
- **Refuse an untracked legacy `<tasksDir>/backlog.json`.** Accepted for the
  switch only, since it is the one place that removes the committed file
  and cannot `git rm` an untracked one. `check` and the writers ignore it,
  because a stray file there harms nothing.
- **Define recovery for failures after preflight.** Accepted. The switch
  computes every new file in memory, snapshots what it edits, writes the
  edits (config last), then runs one `git rm` with every removal, last of
  all. `git rm` validates before it removes, so a failure leaves nothing
  staged. Any failure restores the snapshots. A rerun is a clean start, and
  a finished switch is a no-op, so no further recovery path is needed.
- **Add ordinary `init`, CLI `generate` and MCP `regenerate` to the marker
  preflight.** Accepted. All writers share one function, so none can
  report success while `check` fails.
- **Ignore coverage and untracked outputs as a precondition of every
  writer.** Accepted in narrowed form. Each local-mode writer (CLI
  `generate`, MCP `regenerate`, `create_task`, `move_task`, `import` and
  ordinary `init`) runs one preflight in `src/local-output.mjs`: when the
  target is inside a git work tree, each of the four output paths must be
  ignored (`git check-ignore -q`, so a tracked path counts as not ignored)
  and `.generated` must be a real directory. Outside a git work tree, or
  with git missing, the git half is skipped silently. `check` never runs
  it, and `src/backlog.mjs` stays git-free. The unnarrowed form, a hard
  failure when git is unavailable, would break `generate` on hosts that
  have no git, so it is rejected.

Design decisions:

- **One mode-aware set of paths.** `artifactSet(repoRoot, cfg)` in
  `src/backlog.mjs` returns the generated files with their mode, and the
  author-owned files to scan. Local mode names `index.md`, `completed.md`,
  `removed.md` and `backlog.json` under `.generated/`. `paths()` keeps its
  keys, and `history.json` is unchanged. Every consumer listed in Scope
  reads this set. No code outside it spells an artifact path.
- **Local files carry no markers.** Each Markdown file starts with a
  `# Backlog`, `# Completed tasks` or `# Removed tasks` heading and one
  line saying it is generated and ignored by git. The text is a pure
  function of the items, so it stays deterministic.
- **One validator.** `checkGenerated(repoRoot, cfg, data)` in
  `src/backlog.mjs` returns `{ errors, files }`. In committed mode it
  returns the generator's marker errors and the files to compare. In local
  mode it returns the marker-line errors and no files. CLI `check` and MCP
  `validateOp` both call it, so they cannot disagree.
- **Marker rule.** A file fails when a line equals one of the six marker
  comments, ignoring trailing spaces, tabs and `\r`. Text that merely
  mentions a marker passes.
- **Git-using helpers live in `src/local-output.mjs`**, not the core:
  `outputPreflight` (marker scan plus the git half above),
  `nextIdOverride(repoRoot, cfg)` (the ledger preview in local ledger mode,
  otherwise `undefined`), `writeArtifactFiles` (makes `.generated/`, then
  writes), and `ignoreLineFor(tasksDir)`. Init and the switch share
  `ignoreLineFor` and one output-path verifier.
- **`.generated/` itself.** `outputPreflight` refuses a `.generated` that is
  a symlink or not a directory, since `refuseSymlinkedArtifacts` only
  inspects the files. Scan mode writes in place; ledger mode uses
  `writeArtifactsStaged` as in TRL0037, which also removes a `.generated/`
  it created if the write fails before any artifact lands.
- **Ordinary init in local mode** does not create README or index files at
  all, since they are author-owned. It skips the marker-order preflight and
  runs the marker scan. `init --force` and `--switch-to-local` check the
  config through a sibling of `assertNotLedgerMode` in `src/import.mjs`.
- **`--switch-to-local` takes only `--dry-run`, `-h` and the target.** Any
  other flag is a usage error (exit 2, before any write), which covers
  `--import`, `--retire-source` and `--force`. It runs in a new
  `src/switch-local.mjs` so `src/init.mjs` does not grow a second job.
- **AGENTS.md in the switch.** One renderer owns the artifact bullet for
  each mode. The switch replaces the committed-mode bullet when it matches
  byte for byte, and otherwise leaves AGENTS.md untouched and prints a
  warning naming the sentence to edit by hand. This keeps the repo's Loop
  values and needs no parser.
- **Skeleton-only detection.** After the block is stripped, a file counts as
  Trellis boilerplate only when it equals the skeleton's heading and blurb
  from `src/init.mjs` (exported from there), or is blank. Anything else is
  authored and kept.
- **Imports in local mode** run in scan mode only, as TRL0037 requires.
  `trellis import` and `init --import` refuse with `ImportRefused`
  (exit 2, `invalid_request` in MCP) on a leftover marker.
- **Local-mode `backlog.json` `nextId`.** SPEC §8.5 says an uncommitted file
  may differ per clone. CI never reads it.
- **No version bump.** This is part of the unreleased 2.5. TRL0040 carries
  the 0.3.0 bump on the same branch, so `package.json` is untouched here.
- **Reference surfaces.** `scripts/trellis-import.mjs` for flags and exit
  codes, `scripts/trellis-history.mjs` for a git-backed command, and
  TRL0037's `src/ledger.mjs` for the git helper and error class.

Rejected: none outright. The unnarrowed form of the ignore-precondition
finding is declined, as written above.

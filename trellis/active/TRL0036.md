# TRL0036 — Adopt good-agent for Trellis's own task work

## Scope

Follows the adoption pattern good-agent used for taproot-controls (good-agent
GA0006; taproot-controls ESP0249), which also keeps a Trellis backlog.

- Add `good-agent` `0.3.0` (the current npm release) as an exact-pinned
  `devDependency`, with `package-lock.json` updated.
- Install the shipped skills with `npx good-agent init --skill`
  (`.agents/skills/` and `.claude/skills/`, generated copies, never edited).
- Add `good-agent.config.json` with taproot's values: `rules`
  `claude/size` set to `info`; `review.externalReviewer` routing
  Claude-authored work to Codex and Codex-authored work to Claude;
  `review.codex.effort` `high`; `review.claude` model `sonnet` at effort
  `high`.
- Add a `check:agent` script (`good-agent check`) and run it in the
  `backlog` job of `.github/workflows/backlog.yml` after `npm ci`, so the
  guard gates every PR. The job already runs on Node `lts/*`, which meets
  good-agent's Node 22 floor.
- Add `CLAUDE.md` containing `@AGENTS.md`.
- Add the GOOD-AGENT block to `AGENTS.md`, worded like taproot-controls':
  for Trellis's own task work the shipped `write-task`, `work-task` and
  `review-loop` skills replace the pointers to `trellis/playbooks/`. The
  backlog lifecycle stays where it is: where a task file lives, the Loop
  contract seam points and closing a task. The code-review bullet points at
  the `review-loop` skill and keeps its reminder of the findings format.
- Add `npm run check:agent` to the Loop contract's `gates` row.

## Acceptance

- `npm ci && npm run check:agent` exits 0 from a clean checkout.
- `npm run backlog:check` and `node --test` exit 0.
- `npx --no-install good-agent init --skill` run again changes nothing
  (`git status --short` is empty afterwards).
- `AGENTS.md` names the shipped skills for task work and keeps the Loop
  contract table as the source of the seam values.

## Notes

- `trellis/playbooks/*.md` stay unchanged. They are Trellis product
  material: `trellis init` scaffolds them from `templates/trellis/playbooks/`
  and the MCP server serves them as prompts. Only Trellis's own process now
  follows the good-agent skills. Whether `init` should defer to good-agent
  in a repository that already has it is a separate story.
- This changes contributor tooling only. `package.json` `version` stays at
  `0.2.0`, so merging releases nothing (`release.yml` publishes on a version
  change).
- Add a `CLAUDE.md` that holds only `@AGENTS.md`, the layout good-agent
  enforces. That way Claude Code loads the GOOD-AGENT block without
  depending on its version-specific `AGENTS.md` fallback.
- This task changes no Trellis source, so `node --test` (the `gates` row)
  runs once, at the start of step 5, before the closeout. Checkpoints and review rounds use the
  narrow checks, `npm run backlog:check` and `npm run check:agent`. Each
  `--verified` flag names only a run on the current tree.

## Risks

- The guard may report findings in the current `AGENTS.md`. Mitigation: fix
  them in this task. The file is 4,250 bytes, far below Codex's 32 KiB
  budget.

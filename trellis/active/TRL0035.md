# TRL0035 — Dogfood round 2: onboard Taproot in place with the published release

## Scope

- Taproot does the work in its own backlog. Its adoption task, TR01388,
  lives on Taproot branch `je/tr01388/trellis-adoption` at
  `docs/tasks/active/TR01388.md` (`docs/tasks/completed/tasks/TR01388.md`
  after it merges). It replaces `scripts/backlog-readme.mjs`
  with the published package and is the source of truth for the steps.
  This task tracks the Trellis side.
- Taproot's backlog is already Trellis-shaped (`docs/tasks/{active,
  completed/tasks,removed}`), so it is onboarded in place, not with
  `trellis import`. The order, from TR01388:
  1. Write the full config TR01388 specifies (prefix, width, `tasksDir`,
     milestones, priorities, effort, `specVersion`, `idAllocation`
     `"ledger"`, `generatedArtifacts` `"local"`, and `legacy` computed
     across every worktree) before running init. Legacy id allocation is
     frozen across worktrees before final verification. If `legacy` must
     change after that, the candidate is updated, re-verified and re-signed
     before merge; it is never edited in the merge commit.
  2. Run `npx --no-install trellis init --switch-to-local` (TRL0038). It
     leaves Taproot's near-32 KiB `AGENTS.md` untouched, because that file
     has no TRELLIS block.
  3. Run `npx --no-install trellis init --skip
     ci,pr-template,agents,branch-protection`, without `--force`.
     Good-agent detection also skips the playbooks (TRL0040).
- Use only the published package, pinned through Taproot's exact
  devDependency on `@taprootio/trellis@0.3.0`, which TRL0040's version bump
  publishes. Work in a fresh context, and do not read the Trellis source.
- Record friction verbatim in this task's Outcome, and file anything that
  needs a Trellis change as a new story.

## Acceptance

- Immediately before and after each init command, every skipped path
  (`AGENTS.md`, `.github/workflows/`, `.github/pull_request_template.md`,
  `trellis/playbooks/`, `trellis/branch-protection.md`) is compared, with
  any manual edits made outside those comparisons. All are byte-identical,
  and nothing is added. Taproot already tracks a PR template, so an
  added-files check alone would miss an overwrite, and a workflow change
  would force the full-CI fallback.
- On a clean checkout of the adoption branch, `docs/tasks/.generated/`
  is absent, and `npm ci` then `npm run backlog:check` exits 0. After
  generation, all four outputs are ignored by a tracked rule (`git
  check-ignore`) and untracked. `npm run backlog:readme` then writes all four
  files under `docs/tasks/.generated/`. The README's generated block is
  gone, `backlog.json` is no longer tracked, and the two hand-written index
  files are removed by TR01388's own step.
- The ledger is seeded as TR01388 specifies: in the throwaway clone for
  the probe, and in the real checkout only after merge.
- TR01388's throwaway-clone probe, run with `npx --no-install trellis`
  (the pinned binary), passes: a higher id held only in a linked worktree
  is seeded, and two concurrent claims return the next two distinct ids.
- The Outcome lists every friction point found, or states that there were
  none.

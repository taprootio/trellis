# TRL0005 — Build the local viewer (`trellis serve`)

## Scope

- **Command.** `trellis serve [--repo <path>] [--port <n>]` starts a Node
  `node:http` server on `127.0.0.1`. The default port is 4747, and `--port 0`
  picks a free one. It prints the URL and runs until stopped. There are no
  new runtime dependencies. When the served directory is not a git repo, or
  git is missing, the board serves the served tree without overlay or
  claims and lists the reason under `unreadable`. Wire it through `scripts/trellis.mjs` with a
  `--help` entry.
- **Data.** Each request builds its data with `readBacklog` and
  `buildBacklogJson` (`src/backlog.mjs`) from the item files. It never reads
  a committed `backlog.json`, so the viewer works the same in either
  `generatedArtifacts` mode (TRL0038).
- **Worktree overlay.** `git worktree list --porcelain` names every worktree
  of the repo. Bare, missing and prunable entries are listed as unreadable
  and skipped, and a lane with no merge-base (an orphan branch) counts all
  its items as new. For each worktree other than the one served, the viewer
  compares that lane's task tree (its committed state plus its uncommitted
  working tree) with the lane's merge-base against the served HEAD (`git
  merge-base`). Items changed on the served branch after the lane branched
  are therefore not flagged as lane edits. Relative to that merge-base
  tree, an item is in flight on the lane's branch when:
  - it is new in the lane;
  - its front matter or body changed in the lane;
  - it sits in a different status folder in the lane (being closed or
    removed).

  The board shows each in-flight item once, with a badge per branch. A
  worktree whose task tree fails validation is listed with its error count
  instead of being merged in. When the served tree itself fails
  validation, the board shows an error banner with the count and still
  renders every item that parsed.
- **Ledger claims.** In ledger mode (TRL0037), with the ledger ref present,
  `claim`-kind lines (not `seed` or `through`) that have no item file in
  any worktree are shown in a "Claimed, not
  written" list with id, date, branch and title.
- **Views.**
  - A board grouped by milestone in config order, with priority and effort
    on each card.
  - Completed and removed lists, newest first.
  - A task page that renders the item's Markdown, with front matter as a
    header.
  - Search: case-insensitive term matching over id, title, summary and body.
    Results are ranked title, then summary, then body hits, and show the
    matching line.
  - Filters by milestone, priority and owner, kept in the query string.
- **Live reload.** Non-recursive `fs.watch` watchers send a Server-Sent
  Events message, debounced to 250 ms, and the page then refetches. They
  watch the following. The `refs` filter matches the first path component
  of the ledger ref (`trellis` for `refs/trellis/ids`), and re-arms one
  level down at a time for nested refs.
  - each worktree's `active/`, `completed/tasks/` and `removed/`;
  - `<git-common-dir>` and `<git-common-dir>/refs`, filtered by name for
    `packed-refs` and the ledger ref, plus the ledger ref's own directory
    once it exists. A ledger seeded after start-up is therefore seen;
  - `<git-common-dir>/worktrees`. When it changes, the worktree list is
    re-read and the watchers are re-armed, so a lane added after start-up
    appears.

  Each worktree's tasks root is also watched for subdirectory creation,
  and after every rebuild any missing or errored watcher is re-armed, so a
  branch switch that removes `completed/tasks/`, or a first close that
  creates it, does not stop live reload. Generated files and `.generated/`
  are ignored. Recursive watching is
  not used, because Linux lacks it on the package's Node 18 floor.
- **Local only.** Requests whose `Host` header is not `127.0.0.1:<port>`
  or `localhost:<port>` get 403, so a DNS-rebinding page cannot read the
  backlog.
- **Read-only.** No route changes a file, a ref or git state.
- **Markdown rendering.** A small in-repo renderer (`src/markdown.mjs`)
  covers headings, paragraphs, lists, code spans and blocks, links,
  emphasis and tables, escaping all HTML. Link and image targets are
  limited to `http`, `https`, `mailto` and relative paths (never starting
  with `//`); anything else renders as plain text.
- **Routes.** `GET /` (the board), `GET /api/backlog`, `GET /events` (SSE)
  and `GET /task/<ID>`.
  - `/api/backlog` is the `backlog.json` shape plus `inFlight: [{id,
    branch, change}]` (`change` is `new`, `edited` or `moved`), `claims:
    [{id, date, branch, title}]` and `unreadable: [{path, reason}]`.
  - The task page checks the id against `idPrefix`/`idWidth` and looks it
    up in the served items plus the lane overlay, never building a file
    path from the URL. An in-flight item is shown in its lane's version
    with the branch badge. An unknown id is 404. Markdown the renderer does not cover is shown as
  text.

- **Release.** This story merges after TRL0040 and bumps `package.json`
  and `package-lock.json` from 0.3.0 to 0.4.0 in its PR. That publishes the
  release TR01389 pins.

## Acceptance

- `node --test` covers these, using a temporary repo with one linked
  worktree:
  - `GET /api/backlog` returns the backlog shape.
  - New, edited and moved items in the linked worktree come back with that
    branch, before and after the lane commits them, while unmerged.
  - An item edited on the served branch after the lane branched is not
    shown as a lane edit.
  - The server starts and serves a repo with no `backlog.json` and no
    `.generated/` folder.
  - `--port 0` binds a free port, the default is 4747, and the listener is
    `127.0.0.1` only.
  - Search ranks a title hit above a body hit.
  - A ledger claim without a file is listed.
  - A `<script>` in a task body is escaped, and `[x](javascript:alert(1))`
    renders no link.
  - A request with `Host: evil.example` gets 403.
  - A ledger seeded, and a worktree added, after the server starts both
    reach an open page.
  - Removing and recreating a worktree's `completed/tasks/` keeps live
    reload working.
  - `[x](//evil.example)` renders no link, and `GET /task/../SPEC.md` is
    404.
  - Opening a lane-only item returns 200 with its lane badge.
  - Deleting a lane's worktree directory leaves the board rendering, with
    that lane under `unreadable`.
  - A write method on any route returns 405.
- Run by hand in this repo, `trellis serve` prints a URL whose board lists
  every active item, and editing an item's title in a linked worktree
  updates the open page within two seconds.
- `npm run backlog:check` and `node --test` exit 0.

## Notes

- Revised 2026-11-19 at the owner's request. It covers the worktree overlay,
  claims, search and filters, and moves from Future to v1. TRL0008 keeps the
  dependency graph.
- A repo can run it from its local dev environment. Taproot plans a Tilt
  `local_resource` that runs `trellis serve`.
- Deployment and SSO stay deferred (TRL0012, TRL0013).
- Rejected: building on the committed `backlog.json`. TRL0038 can remove
  it, and it never holds in-flight worktree edits.

## Risks

- Watch storms when a worktree checks out a branch that touches many items.
  Mitigation: the 250 ms debounce, and one rebuild per event batch.
- Large backlogs. Taproot has about 1,300 items across three folders and
  several worktrees. Mitigation: cache the parsed tree per worktree, keyed by
  each file's mtime, and rebuild only what changed.

# TRL0005 — Build the local viewer (`trellis serve`)

## Scope

This story is the board over one checkout, the served tree. TRL0041 adds
the other worktrees' in-flight edits and the ledger's open claims on top
of it.

- **Command.** `trellis serve [--repo <path>] [--port <n>]` starts a Node
  `node:http` server on `127.0.0.1`. The default port is 4747, and `--port 0`
  picks a free one. It prints the URL and runs until stopped. There are no
  new runtime dependencies. Wire it through `scripts/trellis.mjs` with a
  `--help` entry.
- **Data.** Each rebuild reads the served tree with `readBacklog`
  (`src/backlog.mjs`). It never reads a committed `backlog.json`, so the
  viewer works the same in either `generatedArtifacts` mode (TRL0038).
  - `/api/backlog` is the `buildBacklogJson` shape. Its `nextId` follows
    TRL0037's rules: the scan value in scan mode; in ledger mode, the
    ledger preview computed through `src/ledger.mjs` when the ref exists
    and is a valid ledger (TRL0037's format check), otherwise `null`.
  - Items that fail validation still render. Routing uses the filename id,
    which the scan already checked against `idPrefix`/`idWidth`. Items
    that cannot be grouped (a missing or unknown milestone) appear in an
    "Needs attention" section, and a banner shows the error count.
  - When the config cannot be loaded at all, every route except `/events`
    returns 500 with the config errors as text, and the page shows them.
- **Views.**
  - A board grouped by milestone in config order. Each card shows
    priority and effort. Effort follows SPEC §6.3, which TRL0015 deferred
    to the viewer: `label · N` under a custom scale, the configured emoji,
    or the configured image served from `trellis/assets/` with the label
    as its alt text.
  - Completed and removed lists, newest first.
  - A task page that renders the item's Markdown, with front matter as a
    header.
  - Search: case-insensitive term matching over id, title, summary and
    body. An exact id match ranks first, then a partial id match, then
    title, summary and body hits, in that order. Each result shows the
    matching line.
  - Filters by milestone, priority and owner, kept in the query string.
- **Escaping.** Every repository-derived value that reaches HTML (titles,
  front matter, summaries, search excerpts, owner handles) is escaped for
  its context, not only the Markdown body.
- **Markdown rendering.** A small in-repo renderer (`src/markdown.mjs`)
  covers headings, paragraphs, lists, code spans and blocks, links,
  emphasis and tables, escaping all HTML. Markdown it does not cover is
  shown as text.
  - Link and image targets are parsed with `new URL(target, <item's own
    URL>)`. Only `http`, `https` and `mailto` targets, and relative
    targets that resolve to the viewer's own origin, are kept. Anything
    else, including a target that normalizes to another host (`//host`,
    `/\host`), renders as plain text.
  - A relative link to a known task file (for example
    `../active/TRL0012.md` from another task) is rewritten to
    `/task/<ID>`. Other repository paths render as plain text.
- **Routes.** `GET /` (the board), `GET /api/backlog`, `GET /events` (SSE),
  `GET /task/<ID>` and `GET /assets/<path>` (effort images only, from
  `trellis/assets/`, path-checked to stay inside it).
  - The task page checks the id against `idPrefix`/`idWidth` and looks it
    up in the parsed item set, never building a file path from the URL. An
    unknown id is 404.
  - A write method on any route returns 405.
- **Local only.** Requests whose `Host` header is not `127.0.0.1:<port>`
  or `localhost:<port>` get 403, so a DNS-rebinding page cannot read the
  backlog.
- **Read-only.** No route changes a file, a ref or git state.
- **Live reload.** Non-recursive `fs.watch` watchers send a Server-Sent
  Events message, debounced to 250 ms, and the page then refetches.
  Recursive watching is not used, because Linux lacks it on the package's
  Node 18 floor.
  - They watch the tasks root, `active/`, `completed/`,
    `completed/tasks/` and `removed/`, plus `trellis/` for the config and
    roster.
  - A directory that does not exist yet is armed when its parent reports
    it. After every rebuild, any missing or errored watcher is re-armed, so
    a branch switch that removes `completed/tasks/`, or a first close that
    creates it, keeps reload working.
  - Generated files and `.generated/` are ignored.
- **Cache.** Parsed items are cached per file, keyed by path, size and
  mtime. Every path a watch event names is re-read regardless of mtime,
  so a timestamp-preserving replace still refreshes.
- **Release.** No version bump: TRL0041 carries the release.

## Acceptance

- `node --test` covers these, using a temporary repo:
  - `GET /api/backlog` returns the backlog shape. Its `nextId` is the scan
    value in scan mode, and `null` in ledger mode without a ref.
  - The server starts on a repo with no `backlog.json` and no
    `.generated/` folder.
  - `--port 0` binds a free port, the default is 4747, and the listener is
    `127.0.0.1` only.
  - Search puts an exact id match first, and a title hit above a body hit.
  - A `<script>` in a task body and in a task title is inert text.
  - `[x](javascript:alert(1))`, `[x](//evil.example)` and
    `[x](/\evil.example)` render no link.
  - A link from one task to another task file goes to `/task/<ID>`.
  - A request with `Host: evil.example` gets 403, and a write method gets
    405.
  - `GET /task/../SPEC.md` and `GET /assets/../../package.json` are 404.
  - An item with no milestone appears under "Needs attention", and an
    unloadable config makes `/api/backlog` return 500 with the error.
  - A custom effort scale renders `label · N`, and an image scale renders
    an `<img>` with the label as alt text.
  - Removing and recreating `completed/tasks/` keeps live reload working,
    and a timestamp-preserving replacement of an item refreshes its title.
- Run by hand in this repo, `trellis serve` prints a URL whose board lists
  every active item, and editing an item's title updates the open page
  within two seconds.
- `npm run backlog:check` and `node --test` exit 0.

- Rejected: building on the committed `backlog.json`. TRL0038 can remove
  it, and it never holds in-flight worktree edits.

## Risks

- Watch storms during a branch switch that touches many items.
  Mitigation: the 250 ms debounce and one rebuild per event batch.
- Large backlogs (Taproot has about 1,300 items). Mitigation: the per-file
  cache, so a rebuild re-parses only what changed.

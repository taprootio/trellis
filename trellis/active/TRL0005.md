# TRL0005 — Build the local viewer (`trellis serve`)

## Scope

This story is the board over one checkout, the served tree. TRL0041 adds
the other worktrees' in-flight edits and the ledger's open claims on top
of it.

- **Command.** `trellis serve [--repo|--target <path>] [--port <n>]` starts a Node
  `node:http` server on `127.0.0.1`. The default port is 4747, and `--port 0`
  picks a free one. It prints the URL and runs until stopped. There are no
  new runtime dependencies. Wire it through `scripts/trellis.mjs` with a
  `--help` entry.
- **Data.** Each rebuild reads the served tree with `readBacklog`
  (`src/backlog.mjs`). It never reads a committed `backlog.json`, so the
  viewer works the same in either `generatedArtifacts` mode (TRL0038).
  - `/api/backlog` is the `buildBacklogJson` shape. Its `nextId` follows
    TRL0037's rules: the scan value in scan mode; in ledger mode, the
    ledger preview computed through `src/ledger.mjs` when the ref is a
    valid ledger, otherwise `null`. The preview is computed on every
    `/api/backlog` request, never cached, because a claim moves the ledger
    without touching any task file.
  - Items whose front matter parsed render even when they fail
    validation. Files that did not parse (for example unterminated front
    matter) are listed in a diagnostics section instead. Every record,
    route, search result and API entry uses the filename id, which the
    scan already checked against `idPrefix`/`idWidth`, never the authored
    `id` field. When one filename id appears in more than one status
    folder (for example a close left a copy in `active/`), the canonical
    copy for the board, search, API and task page is the most-closed one
    (`removed/`, then `completed/tasks/`, then `active/`). The other paths
    are listed in diagnostics. Active
    items that cannot be grouped (a missing or unknown milestone) appear in
    a "Needs attention" section, and a banner shows the error count.
  - Completed and removed items render in their lists whatever their
    metadata. A null `milestone`, `priority` or `effort` (TRL0039's legacy
    items) is a blank cell with no effort display, and such items never
    count toward "Needs attention".
  - An unusable config is any `loadConfig` error or failed config
    validation (including a JSON root that is not an object, such as
    `null`; today `validateConfig` throws on it, so this task adds a
    root guard that reports it as a config error), including valid JSON without `milestones`. Then every
    backlog-dependent GET route returns 500 with the config errors as
    text, and the page shows them. The `Host` check (403) and the method
    check (405) still run first.
- **Views.**
  - A board grouped by milestone in config order. Each card shows
    priority and effort. Effort follows SPEC §6.3, which TRL0015 deferred
    to the viewer: under a custom scale, every card whose effort resolves
    shows `label · N`, plus the configured emoji or the configured image served from
    `<tasksDir>/assets/`, with the label as the image's alt text. An
    effort that does not resolve shows an empty cell, and its validation
    error stays visible.
  - Completed and removed lists, newest first.
  - A task page that renders the item's Markdown, with front matter as a
    header.
  - Search: case-insensitive term matching over id, title, summary and
    body. An exact id match ranks first, then a partial id match, then
    title, summary and body hits, in that order. Each result shows the
    matching line.
  - Filters by milestone, priority and owner, kept in the query string.
- **Escaping.** Every repository-derived value that reaches HTML (titles,
  front matter, summaries, search excerpts, owner handles) is escaped for
  its context, not only the Markdown body.
- **Markdown rendering.** A small in-repo renderer (`src/markdown.mjs`)
  covers headings, paragraphs, lists, code spans and blocks, links,
  emphasis and tables, escaping all HTML. Markdown it does not cover is
  shown as text.
  - Repository-relative targets are first resolved against the source
    item's directory on disk (for example `<tasksDir>/active/`), then
    looked up in the scanned task set. Other targets are parsed with `new
    URL(target, <viewer origin>)`. Only `http`, `https` and `mailto` targets, and relative
    targets that resolve to the viewer's own origin, are kept. Anything
    else, including a target that normalizes to another host (`//host`,
    `/\host`), renders as plain text.
  - A relative link to a known task file (for example
    `../active/TRL0012.md` from another task) is rewritten to
    `/task/<ID>`. Other repository paths render as plain text.
- **Routes.** `GET /` (the board), `GET /api/backlog`, `GET /events` (SSE),
  `GET /task/<ID>` and `GET /assets/<path>` (effort images only, from
  `<tasksDir>/assets/`). The asset path is checked after resolving
    symlinks (`realpath`), so a link pointing outside the asset root is
    404. Responses carry an explicit image content type, and SVG responses
    also carry `Content-Security-Policy: default-src 'none'; style-src
    'unsafe-inline'; sandbox`, so opening an SVG directly cannot run
    script on the viewer's origin.
  - The task page checks the id against `idPrefix`/`idWidth` and looks it
    up in the parsed item set, never building a file path from the URL. An
    unknown id is 404.
  - A write method on any route returns 405.
- **Local only.** Requests whose `Host` header is not `127.0.0.1:<port>`
  or `localhost:<port>` get 403, so a DNS-rebinding page cannot read the
  backlog.
- **Read-only.** No route changes a file, a ref or git state.
- **Live reload.** Non-recursive `fs.watch` watchers send a Server-Sent
  Events message, debounced to 250 ms, and the page then refetches.
  Recursive watching is not used, because Linux lacks it on the package's
  Node 18 floor.
  - They watch the tasks root, `active/`, `completed/`,
    `completed/tasks/` and `removed/`, plus `trellis/` for the config and
    roster. When the tasks root itself is missing, they watch its nearest
    existing ancestor, and they re-attach when a directory is replaced at
    the same path.
  - A directory that does not exist yet is armed when its parent reports
    it. After every rebuild, any missing or errored watcher is re-armed, so
    a branch switch that removes `completed/tasks/`, or a first close that
    creates it, keeps reload working.
  - Generated files and `.generated/` are ignored.
- **Cache.** `readBacklog` gains an opt-in item reader (a parameter
  defaulting to today's file read). The viewer passes a cached reader
  that returns front matter and body per file, keyed by path, size and
  mtime. Shared validation still runs over the result against the current
  config and roster. The reader resolves each task path (`realpath`)
  before reading. It skips, with a diagnostics entry, any candidate whose
  resolved path leaves the served checkout or whose target is not a
  regular file (a FIFO, socket or device), so `/task/<ID>` cannot expose
  a file from elsewhere and a read can never block. The same guard covers
  every file the viewer reads: the config and roster (an unreadable one
  is a diagnostics entry, or the 500 config response) and effort images
  (404). Filename matching
  uses one shared matcher that treats `idPrefix` literally (escaped, not
  interpolated into a regex). Viewer routes and TRL0037's ledger scans
  reuse it. Every path a watch event names is re-read regardless
  of mtime. An event without a filename invalidates every cached item
  under that directory.
- **Release.** No version bump: TRL0041 carries the release.

## Acceptance

- `node --test` covers these, using a temporary repo:
  - `GET /api/backlog` returns the backlog shape. Its `nextId` is the scan
    value in scan mode, and `null` in ledger mode without a ref.
  - The server starts on a repo with no `backlog.json` and no
    `.generated/` folder.
  - `--port 0` binds a free port, the default is 4747, and the listener is
    `127.0.0.1` only.
  - Search puts an exact id match first, and a title hit above a body hit.
  - A `<script>` in a task body and in a task title is inert text.
  - `[x](javascript:alert(1))`, `[x](//evil.example)` and
    `[x](/\evil.example)` render no link.
  - A link from one task to another task file goes to `/task/<ID>`.
  - A request with `Host: evil.example` gets 403, and a write method gets
    405.
  - `GET /task/../SPEC.md` and `GET /assets/../../package.json` are 404,
    with `tasksDir` set to a nested folder such as `docs/tasks`.
  - A legacy completed item with null milestone, priority and effort
    renders in the Completed list and not under "Needs attention".
  - An item with no milestone appears under "Needs attention", and an
    unloadable config makes `/api/backlog` return 500 with the error.
  - A custom effort scale renders `label · N`, and an image scale renders
    an `<img>` with the label as alt text.
  - Removing and recreating `completed/tasks/` keeps live reload working,
    and so does removing and restoring a nested `docs/tasks` and then
    editing a title. A first close with `completed/` present but
    `completed/tasks/` absent reloads too.
  - A timestamp-preserving replacement of an item refreshes its title.
  - A task file that is a symlink to Markdown outside the checkout, or a
    FIFO, is skipped and listed in diagnostics, and the viewer stays
    responsive.
  - A `null` config file gives the 500 config response.
  - A directory symlink under the tasks root that points outside the
    checkout contributes no ids to `nextId` or dependency checks; the
    containment check runs before directories are listed or watched.
  - A FIFO in place of the config or roster gives a
    diagnostic, and one in place of an effort image gives 404, with the
    server still responsive.
  - With an `idPrefix` containing a regex metacharacter (such as `R+`),
    valid tasks appear and unrelated Markdown does not.
  - The ledger preview differs before and after a `trellis claim`.
  - An id in both `active/` and `completed/tasks/` opens the completed
    copy, and diagnostics list the active path.
  - An active item with an unknown effort label renders with an empty
    effort cell.
  - A file with unterminated front matter is listed in diagnostics, and an
    item whose authored `id` mismatches its filename opens from search
    under its filename id.
  - A config with no `milestones` makes backlog routes return 500, while a
    foreign `Host` still gets 403.
  - The image fixture renders `Tuna · 5` beside an `<img alt="Tuna">`
    whose URL returns the asset. An asset symlink pointing outside the
    root is 404, and an SVG response carries the sandbox policy.
  - A sibling link from one active task to another under a nested
    `tasksDir` goes to `/task/<ID>`.
- Run by hand in this repo, `trellis serve` prints a URL whose board lists
  every active item, and editing an item's title updates the open page
  within two seconds.
- `npm run backlog:check` and `node --test` exit 0.

## Risks

- Watch storms during a branch switch that touches many items.
  Mitigation: the 250 ms debounce and one rebuild per event batch.
- Large backlogs (Taproot has about 1,300 items). Mitigation: the per-file
  cache, so a rebuild re-parses only what changed.

# TRL0005 — Build the local viewer (`trellis serve`)

## Scope

- **Command.** `trellis serve [--repo <path>] [--port <n>]` starts a Node
  `node:http` server on `127.0.0.1`. The default port is 4747, and `--port 0`
  picks a free one. It prints the URL and runs until stopped. There are no
  new runtime dependencies. Wire it through `scripts/trellis.mjs` with a
  `--help` entry.
- **Data.** Each request builds its data with `readBacklog` and
  `buildBacklogJson` (`src/backlog.mjs`) from the item files. It never reads
  a committed `backlog.json`, so the viewer works the same in either
  `generatedArtifacts` mode (TRL0038).
- **Worktree overlay.** `git worktree list --porcelain` names every worktree
  of the repo. For each worktree other than the one served, the viewer
  compares that lane's task tree (its committed state plus its uncommitted
  working tree) with the lane's merge-base against the served HEAD (`git
  merge-base`). Items changed on the served branch after the lane branched
  are therefore not flagged as lane edits. An item is in flight on that
  branch when:
  - it exists only in that worktree (a new story);
  - its front matter or body differs from the served tree (edited);
  - it sits in a different status folder there (being closed or removed).

  The board shows each in-flight item once, with a badge per branch. A
  worktree whose task tree fails validation is listed with its error count
  instead of being merged in. When the served tree itself fails
  validation, the board shows an error banner with the count and still
  renders every item that parsed.
- **Ledger claims.** In ledger mode (TRL0037), with the ledger ref present,
  claims that have no item file in any worktree are shown in a "Claimed, not
  written" list with id, date, branch and title.
- **Views.**
  - A board grouped by milestone in config order, with priority and effort
    on each card.
  - Completed and removed lists, newest first.
  - A task page that renders the item's Markdown, with front matter as a
    header.
  - Search: case-insensitive term matching over id, title, summary and body.
    Results are ranked title, then summary, then body hits, and show the
    matching line.
  - Filters by milestone, priority and owner, kept in the query string.
- **Live reload.** Non-recursive `fs.watch` on each worktree's `active/`,
  `completed/tasks/` and `removed/` directories, and on the git directory
  that holds the ledger ref (filtering events by name, since the ref may be
  packed into `packed-refs`), sends a Server-Sent Events message, debounced
  to 250 ms. The page then refetches. Generated files and `.generated/` are
  ignored. Recursive watching is not used, because Linux lacks it on the
  package's Node 18 floor.
- **Read-only.** No route changes a file, a ref or git state.
- **Markdown rendering.** A small in-repo renderer (`src/markdown.mjs`)
  covers headings, paragraphs, lists, code spans and blocks, links,
  emphasis and tables, escaping all HTML. Anything else is shown as text.

## Acceptance

- `node --test` covers these, using a temporary repo with one linked
  worktree:
  - `GET /api/backlog` returns the backlog shape.
  - New, edited and moved items in the linked worktree come back with that
    branch, before and after the lane commits them, while unmerged.
  - An item edited on the served branch after the lane branched is not
    shown as a lane edit.
  - The server starts and serves a repo with no `backlog.json` and no
    `.generated/` folder.
  - `--port 0` binds a free port, the default is 4747, and the listener is
    `127.0.0.1` only.
  - Search ranks a title hit above a body hit.
  - A ledger claim without a file is listed.
  - A `<script>` in a task body is escaped.
  - A write method on any route returns 405.
- Run by hand in this repo, `trellis serve` prints a URL whose board lists
  every active item, and editing an item's title in a linked worktree
  updates the open page within two seconds.
- `npm run backlog:check` and `node --test` exit 0.

## Notes

- Revised 2026-11-19 at the owner's request. It covers the worktree overlay,
  claims, search and filters, and moves from Future to v1. TRL0008 keeps the
  dependency graph.
- A repo can run it from its local dev environment. Taproot plans a Tilt
  `local_resource` that runs `trellis serve`.
- Deployment and SSO stay deferred (TRL0012, TRL0013).
- Rejected: building on the committed `backlog.json`. TRL0038 can remove
  it, and it never holds in-flight worktree edits.

## Risks

- Watch storms when a worktree checks out a branch that touches many items.
  Mitigation: the 250 ms debounce, and one rebuild per event batch.
- Large backlogs. Taproot has about 1,300 items across three folders and
  several worktrees. Mitigation: cache the parsed tree per worktree, keyed by
  each file's mtime, and rebuild only what changed.
